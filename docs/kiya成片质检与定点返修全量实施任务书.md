# Kiya 成片质检与定点返修全量实施任务书

## 目标与范围

在同一交付轮实现 **跨分段原声诊断与恢复、花字和叠层返修、推镜调整、字幕返修、节奏与边界返修、网页版本对比**。模块可以分开提交，最终用同一个流程串起来验收。使用已有录播和成片完成离线回归，现场新直播验收延后。

成片出现问题时，系统应说明是哪一版、哪几秒、哪个元素或哪段原声出了问题。能用源素材和执行规则可靠证明的修复，由 Agent 生成新版本并复检。事实、时间或目标不明确时，把原因和定位信息保留到待复核状态。

本轮范围是质量和返修，保持真实投稿关闭。继续使用当前预算与账本规则。用户从网页查看结果；开发可使用终端和日志排查。

## 基线和复用入口

- 任务书编写时，本地基线是 `a78060f`。开工先核对当前 Git 版本、已有改动和部署产物，保留用户在工作区的变更。
- `worker/scripts/cut.py` 和 `worker/scripts/render.py` 负责源片切取、拼接、渲染、媒体交付及报告。
- `worker/clipper/quality.py` 已有文件、音画时长和解码音频帧连续性检查，现有判断应作为回归基线。
- `worker/clipper/agent_live.py` 已有实际 MP4 审片；`worker/clipper/agent_production.py` 有候选状态、版本、报告绑定和局部返修。
- `worker/clipper/protection.py`、`worker/clipper/timeline.py`、`worker/clipper/speech_edit.py` 等已有必保证据、时间映射和字幕修订逻辑，优先复用。
- `admin/src/views/Acceptance.vue` 和 Operations Queue 相关 API 已能展示当前成片、审片、质检和历史。对比功能应从现有候选详情进入。

候选 #5 用作回归证据。旧版标称音轨 38.91 秒，但解码音频在成片 **37.035–38.528 秒**缺少约 **1.493 秒**采样。返修前另有开头花字遮住直播标题，模型描述了问题却没给可执行目标。#5 的硬编码场次、效果 ID、哈希、手工补音文件和临时服务器路径只适用于历史验收。

## 一、原声诊断与恢复

### 阶段检查

1. **原录播输入**。对各必保区间记录来源分段、媒体哈希、原片起止、实际可解码音轨和缺口。FFprobe 可读取容器时长时，仍需用解码帧时间戳和真实采样数确认音频连续性。
2. **剪切与拼接后**。验证每段音频在拼接缝前后的覆盖、零点、相邻解码帧间距及输出时长。处理跨分辨率、短尾、起点接近零、录播分段边界或异常时间戳等输入。
3. **实际成片**。复检音频帧连续性、A/V 起止、容器与解码结果、必保原声及成片映射。区分正常声音停顿和实际采样缺失。正常停顿期间的静音样本仍是有效连续采样。

报告分辨原录播缺音、切取或拼接丢音、渲染输出丢音、检查不可用，并给出可证实的最早异常阶段。列出对应整场秒数、成片秒数、来源分段以及严重程度。无法生成稳定映射时明确记录。

### 恢复条件

- 必保区间的原录播存在、能解码且覆盖明确时，按当前剪辑映射重新取对应该区间的原声。
- 原声单轨场景可在验证视频流和音画时间轴对应后复用已渲染画面。若有额外配乐、前情插片、片尾或其他音轨编排，沿原混音计划重新构建对应音轨。
- 恢复后检查实际采样覆盖、接缝、时间轴、原声与画面对齐、开头与结尾。仅修改音轨时应核验视频流与父版一致。
- 无可验证音源、跨段映射不确定、或修复导致必保区间缺失时停在待复核。静音填充可以是原编辑计划的一部分，不能代替缺失的原声证据。

## 二、实际成片审片与定点返修

### 审片输入和返回结构

每次请求绑定当前媒体哈希、版本和时间轴。提供当前成片、附近有用的原片、当前效果和字幕清单、位置或安全区、必保区间及父版信息。提示模型以上传的实际成片为判断依据，将已删除效果或父版意见引用为历史时标明版本。

每个问题至少记录以下内容。

| 字段 | 用途 |
|---|---|
| 版本和媒体哈希 | 锁定实际看过的成片。 |
| 问题类别与理由 | 例如关键字幕被挡、推镜裁掉嘴部、句尾截断。保留可审核的原始理由。 |
| 时间轴与区间 | 明确是成片秒数还是原片秒数。执行前映射到另一侧。 |
| 实际目标 | 效果 ID、字幕句标识及原文字指纹、或有证据支持的原片剪辑边界。 |
| 建议动作及参数 | 动作与所需字段应按类型验证，参数限制在当前候选及可用素材内。 |
| 预期与风险 | 记录预期改善，以及是否可能碰到必保证据。 |

结构不全、目标不存在、版本已变或证据不足时，转待复核并显示具体原因。模型不直接生成命令、文件路径或任意编辑脚本。排除误报时仍保留原意见和核验理由。

### 本轮支持的原子动作

| 模块 | 支持动作 | 执行与复检条件 |
|---|---|---|
| 花字及叠层 | 移除、移位、缩短持续时间 | 目标必须是当前版本内可定位的效果。核对遮挡直播标题、表情、原字幕或重要画面的区间，使用现有画面安全区和属性校验。 |
| 推镜 | 降低强度、移动中心、改变范围或时机、移除 | 准确定位镜头效果及关键区间。回看关键表情、口型和动作是否完整，避免画面边缘裁切和突兀切换。 |
| 字幕 | 校正经证据核对的文字、移位、调整起止、拆句或缩短 | 绑定原句与转写版本，核对原声、阅读时长和遮挡。否定词、说话对象、上下文和原意必须保留。缺原声或引用不确定时待复核。 |
| 节奏与剪辑边界 | 缩短有证据的冗余停顿、调整进出点、延长被截断的声尾 | 只能在明确可用素材和允许区间内操作。保护前因、触发、回应、反转和反应。重新计算字幕、效果、必保证据及原片到成片时间映射。 |

### 执行顺序与冲突

1. 音轨技术问题优先处理。成片有采样断点或出入点音画不完整时，先恢复原声再做语义审片。
2. 有时间轴变更时先处理节奏与剪辑边界，然后重算派生时间。字幕、推镜和叠层按更新后的引用和区间执行。
3. 对同一效果、同一句字幕、同一段剪辑时间轴的冲突建议，执行明确无冲突的部分。互斥或依据不足的动作进入待复核。
4. 每轮写入父版本、新版本、操作、时间区间、媒体哈希和复检结果。复用相同输入与检查点。渲染失败可续跑，重复请求不重做已成功步骤或重复收费。
5. 沿用并说明现有返修轮次上限和预算约束。达到上限、用尽预算或返修后问题仍无法证实时，把结果交给人工复核。已通过版本仅在新版本完整通过后才切换。

## 三、网页返修前后对比

- 入口放在「场次 → 新场验收 → 候选详情」。默认显示当前有效版本、可播放结果和主要问题，历史版本可展开。
- 以两版对照展示问题、实际改动、成片定位、必保证据、技术复检和内容审片。旧版和新版本同时打开时，各自匹配自己的质检、审片与媒体哈希。
- 问题条目可点击跳到实际成片秒数。时间轴发生变化时，优先通过同一原片锚点映射到两个版本，避免把相同的成片秒数当成同一内容。
- 未入库的历史预览可在有授权且通过归属校验时播放，并明确标状态。待复核、失败、可播放、已入库要有独立标识。失效媒体仍可查看历史理由和时间区间。
- 复用现有媒体鉴权、归属验证和 Range 播放。生产与隔离队列的同名场次各读自己的数据。页面刷新、展开、播放和切换版本保持只读。

## 四、离线验收矩阵

| 用例 | 通过标准 |
|---|---|
| #5 音轨时长足够但内部缺采样 | 旧版被拦住并定位约 1.49 秒断点。回归包含可验证原声恢复和重新复检。 |
| 正常停顿或背景低声能 | 音频帧连续时通过，保留正常停顿。 |
| 两段异分辨率、短尾、原始缺音 | 异分辨率素材可正确拼接。短尾采样完整可对照。原录播缺音可定位并进入待复核。 |
| 花字遮挡与无问题花字 | 只修改命中的效果。原字幕、前因、原声和不相关效果保留。 |
| 裁脸推镜与正常推镜 | 问题镜头可按目标调整，正常镜头不会被误改。 |
| 字幕遮挡、错位或过长 | 只改指定句，原意与关键台词保留，成片画面可回看。 |
| 冗长停顿、句尾截断与语义依赖停顿 | 有证据的修复生效。必要的铺垫、停顿和反应仍完整。 |
| 多种返修建议同场出现 | 正确处理依赖与冲突。旧坐标、旧版本和缺项建议不会误改成片。 |
| 历史版本、重复请求与失败恢复 | 保留父版和旧审片，重复执行复用检查点。运行中断可续跑，失败不会更新有效库存。 |
| 网页查看与媒体安全 | 网页可定位、跳转、比较和播放。生产与隔离队列不串数据，媒体归属和版本错误时拒绝读取。 |

对比报告应给出媒体或夹具版本、期望、实测、测试命令及产物位置。#5 或其他真实旧素材可用时直接复用。真实素材缺失的用例可用可复现的模拟或 FFmpeg 夹具，并明确证据类型。在本地或隔离目录复跑本轮范围，不等待下一场直播。
