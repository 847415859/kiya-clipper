# 历史场次网页隔离试跑

## 目标

管理员能从「场次」选择已有历史场次和一个候选，在网页上发起一次隔离试跑，并在「新场验收 → 隔离验收队列」查看进度、质检和成片。开发和本地测试使用夹具，不等待主播开播。

## 页面流程

1. 在历史场次操作区增加「隔离试跑」。展示候选列表、素材可用性和未满足的条件。已有候选文件和对应原始媒体均可读时才允许提交，缺段时显示缺失范围或段数。
2. 提交前显示场次、候选编号、将运行的步骤和费用上限。需要付费模型时显示上限并由管理员确认；预算或成本类型无法确定时应在提交前说明，并拒绝启动需要付费的步骤。
3. 提交后显示任务 ID 和查看详情的入口。详情复用已有验收页，显示排队、运行、预算暂停、待复核及完成状态，附上阶段、原因和可播放产物。

## 实现约束

- 「新场验收」继续只读。在场次操作区新增独立的管理员提交入口，复用现有身份认证并检查操作权限。
- 由服务端根据场次和候选编号解析文件。客户端只提交场次和候选标识及所需确认信息。服务端检查候选与素材归属、路径越界、符号链接和实际可读性。
- 复用现有制作与验收数据结构。评估 `OperationsQueueService`、`ops_prepare.py`、`agent_produce.py` 的输入输出和状态格式，确保历史试跑从已有候选衔接制作阶段。现有生产补入队逻辑依赖真实下播事件，历史试跑应有独立来源标记和任务入口。
- 隔离队列、状态、锁、账号用量记账和成片目录使用现有验收根目录下的相应位置。需要付费时还须符合现有全局费用限制。试跑产物仅进入隔离验收库存，禁止自动投稿。
- 提交异步落盘。双击、刷新重试和并发提交应返回同一个正在进行的任务。Worker 重启后可从有效检查点恢复，保留每次明确重跑的历史记录。进程失败要在页面留下可读原因。
- 隔离 Worker 的启动方式和目录权限纳入部署说明。后台部署后，管理员的日常试跑和结果查看都在网页完成。

## 验收

- 用本地夹具验证从网页提交、Worker 领取、状态更新到验收页展示的完整链路。至少覆盖任务成功、素材缺失、预算不足和 Worker 失败。
- 验证无权限访问、候选归属错误、路径越界、并发重复提交和生产同名场次隔离。检查成片能播放、拖动，审片、质检和媒体版本对应。
- 本地测试不调用付费模型，不投稿。交付时提供前后端和 Worker 测试结果、部署与回滚说明。实际历史录像试跑留作部署后的独立验收。
