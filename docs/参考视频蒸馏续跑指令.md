# 参考视频蒸馏续跑指令

接续现有参考视频研究，从几十 GB 的参考库中提炼 **AI 能独立用于选段和编排的剪辑判断**。每条判断都要说明什么时候采用、什么时候跳过、证据不足时怎么处理。

本轮先完成参考库内的提炼和验证，无需等待用户提供新的 kiya 素材。后续有合适的 kiya 原素材时，再单独做迁移验证。届时由 kiya 素材自身决定选段、叙事顺序、时长、字幕和画面。参考片的具体时间、原话、人物形象及特效素材仅用于研究证据。

## 1. 从已有成果接续

先读取 `worker/output/_reference_study/` 下的文件，再检查原片索引、转写、抽帧、请求账本和证据文件。

| 文件 | 用途 |
| --- | --- |
| `handoff/NEXT_BATCH.json` | 续跑入口和当前阶段 |
| `five_research_v1/editing_decision_candidates.json` | 首轮剪辑判断候选及证据 |
| `five_research_v1/editing_decision_reference_check.json` | 三条补充参考的离线复核 |
| `five_research_v1/acceptance.json` | 样板验收记录和待复核项 |

目前已有五条提炼样本和三条补充参考复核。现有证据初步支持两项判断：用真实画面线索解释人物反应，以及选段时核对前后是否属于同一互动。**节奏压缩缺少经连续声画支持的正例，本轮优先补齐。**

如果续跑入口仍将 kiya 试剪列为下一项，将它调整为后续迁移验证，本轮按参考库蒸馏优先执行。复用已有成功请求、审核记录和账本。旧请求缺原始 JSON 时保留缺证据标记。只有缺口会改变规则判断，且现有原片及产物无法补证时，才考虑定向调用。

## 2. 盘点参考库并选样

1. **盘点整库。** 建立或更新清单，至少记录 BV 号、发布日期、时长、题材、原片可用性、已有分析和证据缺口。沿用既有范围，近期可洛作品优先，优先选原片可用、非回放、15 分钟以内的作品。
2. **先新增精看 5–8 条。** 尽量覆盖多人互动、单人表达、画面或道具承担关键信息、延迟回应和后续切换话题。主动纳入可能推翻候选判断的反例。另留几条未参与规则提炼的作品，供第一版规则定稿后验证。
3. **先建立全片骨架，再深拆关键窗口。** 用已有转写、稀疏抽帧、字幕和章节索引定位事件。对影响剪辑判断的区间回看连续画面和原声，逐段记录铺垫、变化、反应、字幕、声音和收束。整库可持续建立索引，精拆优先安排给能补齐证据的样本。
4. **分开统计处理深度。** 分别汇报已建立索引、已找到候选事件、已完成案例深拆和已参加留样验证的作品。请求覆盖到片尾或全片有抽帧，只计入对应的覆盖或索引统计。

## 3. 按优先顺序提炼剪辑判断

| 优先级 | 要回答的问题 | 每个案例要抓的证据 |
| --- | --- | --- |
| 1 | 什么时候能压缩停顿？ | 找到确实只有等待或重复的正例，也找出停顿里有表情、动作、重音、笑声或伏笔的反例。回看删段两侧，检查动作和原声能否自然接上。 |
| 2 | 从哪里进、在哪里结束？ | 标出第一次能理解事件的线索、改变理解的触发、完整回应和下一话题的开端。记录哪些前情必须保留，哪些取决于切片目标。 |
| 3 | 什么时候切画面或突出字幕？ | 区分提供新证据的商品页、截图、物件和对照画面，以及承担情绪强调的效果。记录何时原画面就够，何时要回到反应主体，字幕如何帮助辨认说话人和关键词。 |
| 4 | 声音怎么承接？ | 找出切画面后仍要保留的原声、关键回应声尾、笑声和停顿。分别记录原声事实，以及对配乐或音效作用的解释。 |

把案例归纳为可执行的条件。例如，前后属于同一互动，删去中间段后因果仍可理解，且连续声画支持中间没有有效信息或反应时，才建议压缩。任一条件缺证据时，维持原边界并标记待复核。其他候选判断也写到这个粒度。

标题和封面可记录已有证据，留作后续独立研究项。本轮优先完成切片和编排。

## 4. 为每条规则写清证据和回退

同时维护可读报告和机器可读规则表。每条候选至少包含以下内容。

- **目标与触发条件**。它解决的是选段、画面、字幕、声音还是收尾问题。AI 需要识别到什么。
- **实际动作与替代手法**。满足条件时如何处理。原画面、对白、字幕或局部放大都能说明问题时，如何按素材选择。
- **跳过条件与回退动作**。何时维持原边界、另开候选、保留原声或标记待复核。
- **正例、反例和证据引用**。写明 BV 号、原成片时间、证据文件和证据类型。区分源片观察与编辑解释。
- **验证结果与状态**。逐条记录留样判断与误用。单例支持的先保留为案例假设。跨视频有支持且留样能检验适用边界时，再列为可继续验证的规则候选。

分别记录字幕可见帧、抽帧请求时间、原片解码 PTS 和 ASR 时标。遇到时间单位异常，保留原值与推导值。涉及切换首帧、原声逐字或音画同步的判断，回到对应原片证据核对。个别位置有疑问时标记待复核，有独立证据的其他案例继续推进。

## 5. 做留样验证，通过后自动扩批

先固定第一版规则，再用预留作品逐条判断 **适用、不适用、证据不足**，每次判断都写明依据。已有三条参考复核继续保留为研究记录，新增留样单独登记验证过程。

重点检查三类误用。

1. 把换话题后的回应接到前一段互动。
2. 把承担必要前情或有效反应的停顿删掉。
3. 只凭 OCR、像素变化或模型时间戳，推荐具体镜头切点或声尾。

如果留样能分清适用边界，且候选没有反复触发上述误用，**自行扩到 20–30 条参考作品，分批研究**。继续采用全片索引、关键段精拆、按规则补正反例的流程。每批结束后更新规则表、证据索引、成本和续跑状态。

如果某条规则反复误用，缩窄适用条件或退回案例假设，继续推进其他规则。如果验证样本不足，写明缺少哪类证据。完成 20–30 条扩批后，交付规则和覆盖情况，供后续决定是否扩到整个参考库。

## 6. 预算和自行执行范围

- 沿用 **250 元累计总上限**，其中全片分析池 **170 元**，精拆与复核池 **80 元**。历史消耗及未知用量预留计入同一账本。每批开跑前登记计划请求量、费用估算和停止条件。成功、失败、状态未知和重试都留账，估算与实际账单分开记录。
- 按 **本地复用 → 原片短窗核对 → 必要时调用已授权的阿里付费服务** 的顺序执行。同类 schema、模态或时间错误重复出现时，暂停受影响的调用路径，离线排查后做最小定向验证。本地分析和其他正常路径继续推进。
- 预算或计费口径无法核清时，暂停新增付费请求，继续离线工作。选样、短窗补采、规则调整、留样验证和满足条件后的扩批均可自行执行，无需逐项确认。
- 需要用户决定的事项集中汇报，包括预算触顶后仍需付费、关键证据确实缺失且无替代来源，以及涉及修改生产默认或发布内容的变更。本轮做到研究交付，生产或发布另行授权。

## 7. 本轮交付与首次进展

在现有研究目录和交接入口更新以下产物。

1. **参考库处理清单**。列出完成索引、精拆和留样验证的作品与数量。
2. **剪辑判断报告和机器可读规则表**。列出适用条件、动作、回退、正反例及证据引用。
3. **留样验证结果**。逐条记录哪些判断成立、出现了什么误用，以及如何修订。
4. **请求账本和续跑状态**。列出累计估算、实际账单状态、未知项、复用成果和下一批入口。

收到后直接盘点已有产物并开展首批 5–8 条研究。第一份进展报告应写明补到了哪些正反例、哪些判断已经可以写成候选规则、哪些仍缺证据，以及当前累计费用。按本指令自行验收和续跑。
