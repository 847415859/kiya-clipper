# 多主播支持

> 把「主播」从全局硬编码抽象成可配置的实体。首位主播 kiya 的现有配置、数据、部署完全兼容，无需迁移；新增主播按下面的接入指南即可。

## 一、主播标识（streamer_id）

- 1–32 位，**小写字母开头**，后可跟小写字母 / 数字 / `_` / `-`（例如 `kiya`、`kiya2`、`miko`）。
- 贯穿配置、数据、环境变量、数据库四个层面，是「主播」在系统里的唯一身份。
- 默认主播：环境变量 `KIYA_STREAMER`，不设就是 `kiya`。

## 二、目录与数据隔离

多主播的核心约定：**场次目录的父目录就是主播的输出目录**，所以 `_memory` / `_llm_cache` / `_jobs` 等共享目录只要从 `sess.parent` 定位，就自动按主播隔离。

```
config/
├── kiya.yaml                 # 首位主播配置（兼容旧路径，无需迁移）
├── subtitles.yaml            # 字幕样式（全局共享）
└── streamers/
    ├── _template.yaml        # 新主播接入模板（复制改名即可）
    └── <主播标识>.yaml        # 新主播配置（优先读这里）

worker/output/
├── kiya/                     # kiya 的数据（新结构）
│   ├── <场次>/
│   ├── _memory/              # 精排记忆（按主播隔离）
│   ├── _llm_cache/           # 大模型缓存（按主播隔离）
│   ├── _jobs/                # 任务日志
│   ├── admin_overrides.json  # 后台覆盖配置（热词 / 纠错词 / 默认样式，按主播隔离）
│   └── memory_decisions.json # 精排记忆决定（梗转正 / 禁区 / 权重，按主播隔离）
└── <新主播>/

eval/
├── kiya/
│   ├── reviews/              # 标注（按主播隔离）
│   ├── annotations.csv
│   └── results.csv
└── <新主播>/
```

**向后兼容**：升级前已有的 `output/<场次>/`（没有主播层级）会被识别为默认主播 kiya 的数据，不用搬。规则（Python 的 `streamer.py` 和后端 `WorkerPaths` 一致）：kiya 的 `output/kiya/` 不存在、而 `output/` 下直接有场次（含 `candidates.json` / `transcript.json`）或 `_memory/` 时，继续用 `output/` 本身；评测目录同理（`eval/kiya/` 不存在、`eval/` 下直接有 `reviews/`、`annotations.csv`、`results.csv` 时用 `eval/`）。想迁到新结构，把它们 `mv` 进 `output/kiya/`、`eval/kiya/` 即可（迁移时别有任务在跑），之后自动走新结构。其他主播永远走新结构。

**数据库升级**：已部署的 MySQL 要执行一次 `deploy/admin/migrate_multi_streamer.sql`（可重复执行，数据归到 kiya），步骤见 `deploy/admin/README.md` 的「多主播升级」。全新部署不需要。

## 三、配置分层

| 配置 | 位置 | 说明 |
| --- | --- | --- |
| 主播配置 | `config/streamers/<id>.yaml`，回退 `config/<id>.yaml` | 主播档案、信号权重、词典、梗、禁区 |
| 字幕样式 | `config/subtitles.yaml` | 全局共享 |
| 后台覆盖 | `output/<id>/admin_overrides.json` | 按主播隔离（kiya 兼容旧的 `config/admin_overrides.json`） |
| 精排记忆决定 | `output/<id>/memory_decisions.json` | 按主播隔离（kiya 兼容旧的 `config/memory_decisions.json`） |

## 四、环境变量

| 变量 | 默认 | 说明 |
| --- | --- | --- |
| `KIYA_STREAMER` | `kiya` | 默认主播标识：worker 脚本用它定位配置 / 数据；后台顶部选择器可在运行时切换，不必改它 |

其余 `KIYA_*` 变量（`KIYA_ASR`、`KIYA_RERANK`、`KIYA_AUTO_CUT` 等）保持原义不变。

## 五、新主播接入步骤

1. **建配置**：`cp config/streamers/_template.yaml config/streamers/<主播标识>.yaml`，填必填项（`name`、`uid`、`room_id`、`fan_name`、`hotword_prefix` 等）。
2. **加直播间**：录播姬网页管理界面添加该主播的直播间，开启自动录制（录播姬本身支持多房间，无需额外配置）。
3. **跑链路**：命令加 `--streamer <主播标识>`，或设环境变量 `KIYA_STREAMER=<主播标识>`，例如
   ```bash
   python scripts/screen.py /data/rec --latest --streamer miko
   python scripts/cut.py output/miko/<场次>/candidates.json
   ```
   下游脚本（cut / rerank / render 等）会从 `candidates.json` 路径自动推导主播，不必每个都显式传。
4. **热词表**：`python scripts/hotwords.py sync --streamer miko`（`hotword_prefix` 已在配置里区分主播）。
5. **后台**：后台顶部的主播选择器里选新主播即可，数据、场次、审核、评测、记忆全部按主播隔离；不用改配置或重启。

## 六、改造清单（本次改动）

### 新增
- `worker/clipper/streamer.py`：主播抽象层——`normalize` / `default_streamer` / `streamer_from_args` / `streamer_from_session_dir` / `config_path` / `output_root` / `eval_root` / `reviews_dir` / `resolve_config` / `overrides_path` / `decisions_path`。
- `config/streamers/_template.yaml`：新主播接入模板。
- `worker/tests/test_streamer.py`：抽象层 7 个测试。
- `backend` 的 `StreamerContext` / `StreamerFilter` / `StreamerService` / `StreamerController`：后台主播选择器。

### 改造
- **worker 入口**（`screen.py` / `analyze_danmaku.py` / `transcribe.py`）：加 `--streamer`，输出目录默认 `output/<主播>/`。
- **worker 下游**（`cut.py` / `rerank.py` / `render.py` / `edit_preview.py` / `autoedit.py` / `evaluate.py` / `learn.py` / `memes.py` / `publish_pack.py` / `weekly_report.py` / `subtitle.py` / `hotwords.py` / `try_llm.py`）：配置解析走 `resolve_config`，数据 / 评测目录按主播分层。
- **LLM 缓存**：`rerank.py` / `autoedit.py` 显式传 `cache_dir=sess.parent/_llm_cache`，按主播隔离。
- **运行时配置**：`admin_overrides.json`（热词 / 纠错词 / 默认样式）和 `memory_decisions.json`（梗转正 / 禁区 / 权重）按主播隔离到 `output/<主播>/` 下；`overrides.py` / `kcfg.py` / `learn.py` / `rerank.py` / `publish_pack.py` 的路径解析走 `streamer.py`，kiya 兼容旧的 `config/` 路径。
- **backend**：`schema.sql` 的 `live_session` / `candidate` 加 `streamer_id`（默认 `kiya`），唯一约束改为组合；`KiyaProperties` 加 `streamer`（默认主播）；`WorkerPaths` 的 output / eval / reviews 按主播分层，`streamerStateFile()` 按主播隔离运行时配置；`SessionService` 所有查询按 `streamer_id` 过滤。
- **主播选择器**：后端 `StreamerContext`（ThreadLocal）+ `StreamerFilter`（从 session 读当前主播）+ `StreamerService` / `StreamerController`（`GET /api/streamers`、`POST /api/streamers/current`）；前端 `Layout.vue` 顶部下拉框，切换后整页刷新按新主播加载。
- **监控**：`kiya_monitor.py` 新增 `streamer_cfg_from_yaml()`，从主播配置读 `room_id` / `name`（正则提取，不引入 PyYAML 依赖），环境变量仍可覆盖。

## 七、已知边界（后续优化）

- 主播间对比分析依赖多个主播都攒够数据，暂未实现。
- 字幕样式（`subtitle_style` 表）和贴图库（`assets/stickers/`）目前仍是全局共享的，多主播时可能串，后续按主播拆。
