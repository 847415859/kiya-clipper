## 3. 必须修复的问题

### P0：汇总使用了局部时间，导致成片坐标错误

位置：`worker/output/_reference_study/build_qwen_deep_deliverables.py`。

客户端的 `absolute_observations` 同时保存：

- `start_ms/end_ms`：本次提交片段内时间。
- `absolute_start_ms/absolute_end_ms`：增加片段起点后的成片时间。

汇总脚本复制记录后，后续排序、去重、区间重叠、字幕、听音、内容节点、声画对齐和报告都继续使用局部 `start_ms/end_ms`。

独立重算：第一条有 225 条、第二条 77 条、第三条 36 条记录存在非零起点却使用局部时间，共 **338 条**。第一条长 332.667 秒，汇总节点最晚却只到 60 秒；第三条长 98.950 秒，汇总最晚只到 43.950 秒。

例如：第一条 165 秒开始的调用，局部开头画面被放到了成片 0 秒，与其他块的开头重叠，进而制造错误的“同时发生”声画关系。这个错误不需要新模型调用即可修复。

修复要求：

1. 归一化层明确保存 `local_start_ms/local_end_ms`、`clip_start_ms`，输出统一成片 `start_ms/end_ms`。
2. 只换算一次，校验 `absolute = clip_start + local`，不能重复加起点。
3. 用同一套成片坐标重建去重、覆盖、字幕、声音、关系、图与报告。
4. 旧派生结果标记失效但保留；原始成功调用和缓存继续复用。

### P0：模型时间单位存在未检出的异常

至少两个结构成功结果需要隔离核对：

- `20261119T023511Z_919f6f76`：第一条 305 秒开始、长 27.667 秒的视觉片段，有 9 个画面观察，但模型局部最大结束值只有 **27 毫秒**。
- `20261119T021923Z_3e7d3e09`：第二条 55 秒开始、长 60 秒的音频片段，有 26 个观察，局部最大结束值只有 **126 毫秒**。

这是秒/毫秒、局部/全片原点混淆的强烈线索，但不是足够证据直接乘 1000 或减偏移。两个异常都落在数值范围内，因此仅靠 Pydantic 和越界检查不会发现。

先检查原始返回、实际媒体内容和锚点；可证明的转换保留原值、转换规则和理由。证明不足则隔离其时间，允许保留区间级内容描述，不能作为精确动作和声画对齐依据。确需新调用时只补这类异常小区间。

这也暴露接入层的不足：之前未保存结构失败时的细分诊断和已返回用量。下一阶段应补上可脱敏的诊断、输出哈希、请求状态、返回用量及不确定成本记录，避免盲目重试；不是直接放宽 schema 接受任何结果。

### P1：所谓内容节点与六遍结果仍由固定模板生成

目前 `content_nodes.json` 的节点来自所有观察起止点的数值切分；字段内容包括固定的：

```text
Model observations exist in this time range...
Requires preceding/following context...
Model-derived content segment...
```

这不是事件的触发、回答、揭示、反应、澄清和收束。修复时间轴后也不能把新的时间格子自动当成语义节点。

同样，剪切记录的 `before_state`、`why_here` 仍大量是待检查模板；字幕用描述中是否包含“字幕”等词筛选；声画用时间重叠连接后填写通用作用；每条只有一份几乎相同的配方。这些可以作检索中间层，不是细致制作结论。

必须增加真正的全片语义汇总与针对关键段落的分析：事件是什么、哪条实际台词引出哪次动作、前后状态是什么、保留什么、为什么这样安排。解释可以是模型分析，标明依据和不确定性即可，不需要等人工逐条确认后才允许写。

### P1：编排图截断且不表达编排依赖

当前第一条有 94 个节点，图仅输出前 80 个；图中文字为时间加 `model-observed segment`，再按时间逐个连线。它既丢节点，也没有内容和真实依赖。

改为全片内容骨架图加关键段落子图；总览可压缩节点，但每个细节点必须有归属，不能直接丢弃。边区分时间先后和必要依赖，标签填写具体事件。

### P1：验收 `passed` 不足以证明结构和时间正确

`validate_qwen_deep_v1.py` 主要检查文件、非空证据、未夸大完成状态及目录数是否等于 34；`successful_call_estimate=29` 是写死的。汇总还用 `bool(nodes)` 表示全时段覆盖。

它未检出局部时间被当全片、虚假的重叠、模型单位异常、图截断、模板节点和用量缺失。因此截图里的 `passed/errors=[]` 只能说明这些有限检查通过，不能当作独立内容验收。

重试脚本只是再次调用同类观察入口、缩短窗口，没有独立的问题设计和初分析对照；不能把所有重试称为“独立视觉复核”。

## 4. 不应当继续作为阻塞项的事情

1. **源 EDL 未取得**：本轮只研究成片、明确不分析回放，源 EDL 不在必要验收范围。需要的是有精度说明的成片动作，不是反推原录播全部删除历史。
2. **human_confirmed=false**：符合自主模型研究要求，可以完成模型研究案例；人工确认仍为 false。不能因此认定研究永远不能完成。
3. **作者意图是解释**：允许基于证据提出制作作用解释，不能当作作者亲述事实；不应因无法证明作者内心想法而停止所有编排研究。
4. **production_approved=false**：这是正确状态。先完成可用研究候选，再安排系统实现和样片验收。

## 5. 下一阶段执行计划

### 阶段 A：离线修复，零新增模型调用

- 新增请求账本：请求尝试、响应收到、结构通过、缓存、失败、未知用量分别计数。
- 废止错误节点与声画连接，不把单纯离线重算当作语义结论。

**验收：** 所有有效坐标与源请求一致；已知错位能被测试捕获；缺口计算和用量不含硬编码数值；原产出可追溯。

### 阶段 B：定位失败根因后，只补最小证据

新增调用前先修失败诊断。18 个失败都只有同一句错误，不能据此决定换模型或无限缩短片段。

- 检查已保留缓存中是否有可恢复的内容；没有则如实登记不可恢复，不虚构旧响应。
- 区分 JSON 格式、字段不符、时间单位、越界、模态错误、截断等原因。
- 模型返回之后才出现的结构错误也记为已发生外部处理，用量未知不当零。
- 首先处理第一条的三段视觉缺口和第三条的 0–30 秒；异常结果按隔离后实际缺口补充。
- 以能解决问题的最小区间和针对性问题调用，不重跑全部视频；修复回退仍需遵守预算。

现有校准预算已消耗大量调用，下一轮不能通过换目录重置额度。先交阶段 A 的确定成果，并列阶段 B/C 的请求数量范围及成本依据；已有额外明确授权则自动执行，否则只合并提出一次新增额度需求，继续离线任务。

### 阶段 C：先交一条真正完整的制作研究

第一条必须由模型做语义汇总，而不是 Python 固定字符串：

- 用具体事件描述全片起因、过程、主要看点和收束。
- 内容节点有原话/行为、前情、观看任务和前后依赖。
- 选择关键段落，组合实际画面、声音与原话证据，说明进出时机和制作作用。
- 原图/相邻帧补关键切换与字幕，不把 Qwen 毫秒字段当作逐帧测量。
- 原话、真实弹幕、评论和素材文字分开。
- 至少形成有内容依据的配方候选或明确说明证据不足，不能三条同一模板。
- 复核任务先独立观察媒体再对照结论；同一模型独立上下文不能冒称独立模型验证。

先完成第一条，自动验收后继续另外两条；局部未知隔离，人工不逐句介入。不要求所有字号或音效名都精确测定，但主要内容与动作必须能回看。

### 阶段 D：研究样本扩展与最小系统试验

三条通过模型研究验收后，再扩近期常规互动样本，满足跨独立事件和时间证据门槛。保留低包装与失败案例，不平均混合账号风格。

然后挑 2–3 类有充分依据、当前系统可以执行的制作机制做离线 kiya 样片；先处理事件完整性和信息顺序，再增加插入与声音。保留原版对照，不立刻改生产默认值。
