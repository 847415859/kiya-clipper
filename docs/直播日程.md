# 直播日程与作品预告

“直播日程”填写主播接下来一周的计划；原有“主播周报”继续展示历史统计。日程按当前选中的主播分别保存，使用已有后台账号登录后编辑。

## 填写并确认

1. 打开顶部菜单“直播日程”，选择周。每周从周一开始，统一按北京时间填写。
2. 手工添加安排，或上传 PNG / JPG 周表图片（最多 8MB、1200 万像素）。图片会转换为 JPEG 留作核对。
3. 点击“识别图片日程”才会调用现有视觉模型，可能产生模型费用。识别建议不会自动保存、确认或用于发布；先追加到表格或替换草稿，再逐条检查。
4. 支持直播 / 活动、待定、休息和已取消，每周最多 14 条。时间不明确时留空，结束时间早于开始时间表示跨午夜；备注只作编辑参考，不写入预告。
5. “保存草稿”只保存输入，已确认版本继续生效。勾选已核对，再点“确认并用于发布”，才会启用新版本。“暂停使用已确认日程”会停止后续作品使用这周日程。

同一周被其他页面修改时，保存会提示版本冲突并保留当前输入。先复制需要保留的内容，再点“重新读取已保存版本”核对。离开或切换周时，未保存内容会有提示。

图片识别复用 `DASHSCOPE_API_KEY` 和现有模型设置，默认视觉模型为 `qwen3-vl-plus`；如需单独配置，可在主播配置中添加 `schedule.model`。识别不成功时可以直接手工填写。

## 在作品简介和片尾中展示

1. 在成片编辑页的发布区域，默认勾选“在简介和视频片尾介绍剩余日程”。没有相应周的已确认安排时，不添加预告。
2. 立即发布可将“预计公开时间”留空；定时发布请先填预计公开的北京时间。预览会显示这时对应周的剩余安排。
3. 点击“试渲染日程片尾”可单独检查片尾效果。采用紫色手账风格，左侧人物相框与姓名卡，右侧为网格纸、星期笔刷和手绘标记。每页两条、停留七秒，最多展示前八条，片尾长 7–28 秒；长标题缩略，完整内容在简介中。原周表的旧日程不直接烧进片尾。
4. 完整渲染会自动保存本作品的日程设置，片尾与正片使用同一条渲染流程。正片声音和背景音乐在片尾开始前结束。
5. 一键发布会在基础简介后追加对应日程，不会反复改写或叠加到原简介。“复制完整简介（含日程）”适用于手工投稿。

时间筛选规则：只取预计公开时间所在周；排除取消的安排、过去日期和已到结束时间的安排。没有结束时间且开始已过的直播不再预告，以免介绍已经结束的场次；当天时间待定、休息等全天安排会保留。已开始但尚未到明确结束时间的直播仍会展示。

发布任务会按本次公开时间再次计算，并和所选分辨率成片的日程记录核对。日程修改、暂停或跨过结束时间后，如果片尾内容不同，会在上传前提示重新渲染。关闭介绍时，带旧日程的成片同样需要重新渲染，不能只去掉简介而留下过期片尾。

“先放着”实际上设为未来定时投稿，默认 14 天后，所以按那个日期的周计划核对。希望介绍本周安排时，应选择匹配的立即 / 定时公开时间并提前渲染。在 B站创作中心再次改期后，系统不会自动替换已经上传的片尾；需自行核对并重新制作。立即发布按任务启动时间筛选，上传和平台审核可能继续耗时。

## 文件与部署

在直播日程页可单独上传“片尾人物图”，不会把它当成周表识别。建议使用人物居中的竖图；修改后需重新确认日程、重新渲染。kiya 的默认人物图使用本次提供的参考图，仅取左侧人物区域，原图里的日期与周计划不显示。其他主播可设置 `schedule.portrait_file`（相对仓库的图片路径），常规人物图用 `schedule.portrait_crop: center`；不配置时显示手账插画占位卡。

- 日程：`worker/output/<主播>/_schedule/YYYY-MM-DD.json`，包含草稿、确认版本和启用状态。
- 图片：同目录的 `images/<随机标识>.jpg`。兼容首位主播原有输出目录布局。
- 成片旁的 `.schedule.json` 记录本次日程、时间和文件信息，用于发布核对；搬迁成片时一并保留，文件记录不匹配需重新渲染。
- 本功能不修改已发布的历史作品；已渲染的片尾是固定画面，更新周计划后需重新渲染。
- 更新前端、后端与 worker 后重启后台。上传限制已调整；已有 nginx 配置需将 `client_max_body_size` 更新为 `9m`，以容纳 8MB 图片及表单开销，参见部署文档。
