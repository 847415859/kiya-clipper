# 完整事件识别与多边界剪辑方案

编写日期：2026-11-17。

状态：**待开发方案**。本文说明下一阶段的功能设计和验收方式，不代表文中能力已经实现，也不承诺提升播放或关注转化。

关联文档：[切片内容策略](切片内容策略.md)、[技术方案](技术方案.md)。

## 一、目标与范围

将当前“发现候选时间段、给出一组起止点”的流程，扩展为：

**发现线索 → 识别完整事件 → 合并重复候选 → 生成多种边界方案 → 剪辑师比较与确认 → 更新预览和发布包。**

主要解决的问题：

1. 候选只包含笑声、表情或弹幕爆发，缺少起因。
2. 同一事件被多个时间窗口重复召回，增加审核工作。
3. 精彩行为结束后，还有应当保留的反应、解释或停顿。
4. 单一边界建议无法体现“精简、完整语境、保留余韵”的不同取舍。
5. 修改边界后，字幕、效果、预览或标题仍对应旧版本。

事件不限定为笑点。一次温柔回应、一个自然反应、一段观点表达或一次反差，都可以成立。不为满足固定结构或时长而拼凑素材。

第一版优先处理**连续片段**。复杂的跨时间拼接、远距离回调和多事件合集由人工完成，不作为自动事件重建的默认行为。

## 二、完整事件识别

### 2.1 事件结构

每个事件建议记录以下内容：

| 信息 | 用途 | 缺失时的处理 |
|---|---|---|
| 事件概述 | 用一句话描述实际发生的事情 | 无法说明时进入待复核 |
| 涉及对象 | 说明谁在表达、回应谁、代词指什么 | 标记理解障碍，不猜测身份 |
| 必要前情 | 解释缺少哪些内容会看不懂 | 可为空，但需要说明不需要前情的依据 |
| 核心行为或表达 | 定位事件值得保留的部分 | 缺少可核对核心时不生成推荐切法 |
| 后续反应 | 记录解释、停顿、表情或观众回应 | 允许不存在，不强行补齐 |
| 结束依据 | 说明何时事件已经完整 | 无法确认时标记结束点待复核 |
| 证据位置 | 关联原话、弹幕及实际输入的截图 | 无证据判断不得当作事实 |
| 理解障碍 | 记录圈内梗、原话存疑、录像缺段等 | 保留风险提示和人工处理入口 |
| 关联候选 | 保留粗筛、探索和人工标记来源 | 合并后仍可追溯原始候选 |

不要求每个事件都有“铺垫—笑点—反应”。一句完整且有辨识度的表达，也可以独立构成短事件。

### 2.2 两阶段处理流程

第一阶段复用现有召回，不重新扫描整场视频：

- 热度峰值候选。
- 非峰值探索候选。
- 原话语义召回。
- 人工时间标记。

第二阶段围绕线索重建事件：

1. 读取候选附近的逐字稿和已有截图。
2. 定位核心表达或行为。
3. 向前查找理解核心所必需的前情。
4. 向后寻找反应和自然结束点。
5. 输出事件结构、证据及未解决的问题。

先沿用现有前后文预算。只有发现明确缺口，例如“回答对应的问题不在输入内”“对象没有交代”，才扩展读取，并记录扩展原因与范围。

**上下文范围只用于理解，不直接作为成片长度。**

超出当前素材窗口上限、录像存在缺段，或仍依赖远处前情时，标记为需要人工处理。不能静默截掉缺失部分后宣称事件完整。当前素材窗口上限为 500 秒；如后续调整，应同时检查 Python、后端和编辑器的限制。

### 2.3 区分事实与编辑解释

示例：

> 事实：主播说“这次肯定能成功”，随后操作失败。
>
> 编辑解释：承诺与实际结果形成反差。

两者分别记录。事实必须能定位到素材；编辑解释需要说明所依据的事实，不得反过来充当事实证据。

核验要求：

- 原话必须匹配逐字稿及对应时间。
- 画面描述仅限实际提供的截图，不能补写没有看到的动作。
- 弹幕不能单独证明主播做过某件事。
- 没有可听音频时，不推断声线、语气或“治愈感”。
- 不以 ASR 中存疑的关键词作为事件成立的唯一依据。
- 没找到前情时，不通过编造解释字幕补齐。
- 证据不足的事件保留在待复核队列，不直接丢弃，也不进入正常推荐。

### 2.4 重复事件合并

采用两步判断：

1. 根据时间重叠或邻近关系，找到可能重复的候选。
2. 判断它们是否指向相同的核心表达、行为和前情。

不能只按时间距离合并。同一操作引发的多次反应可能属于一个事件；相邻的两个独立话题则应分开。同一个梗在较晚时间再次出现，可以建立关联，但不能直接合并为一个连续事件。

合并后保留全部召回来源，便于判断事件是由热度发现，还是由语义探索、人工标记补充。

事件使用独立且稳定的编号。边界调整不改变事件编号；重新分析产生新版本。现有投稿绑定和统计中已有的 `event_id` 不直接重写，应保留兼容映射，避免历史去重关系失效。

### 2.5 审核页面：事件卡片

建议展示：

> **事件：自信尝试后失败，随后主动找补**
>
> 核心位置：10:19–10:27。
>
> 必要前情：10:09–10:18 的自信承诺。
>
> 后续反应：10:28–10:42 的停顿和解释。
>
> 理解障碍：无。
>
> 状态：可比较剪辑方案。

提供以下操作：

- 跳到核心位置、回看必要前情、查看结束依据。
- 合并或拆分事件。
- 标记“前情不必要”“反应未结束”“原话有误”。
- 确认或修改事件结构。

人工确认内容应保留。重新分析只能提出新建议，不得覆盖已确认的结构；输入变化后，应提示人工检查旧确认是否仍然适用。

## 三、多种边界方案

### 3.1 方案定义

先比较切法，再选择效果风格。第一轮使用相同素材、原声和字幕设置，避免同时改变配乐、花字和边界，导致无法判断改善来自哪里。

| 方案 | 目标 | 取舍原则 |
|---|---|---|
| 精简版 | 尽快进入事件 | 省略非必要铺垫，保留理解和成立必需的内容 |
| 完整语境版 | 让新观众自然看懂 | 保留问题、对象和必要过程，尽量不依赖额外解释 |
| 保留余韵版 | 保留事件后的情绪和人物表达 | 给反应、停顿或找补留空间，在自然结束点退出 |

允许只输出一个或两个有效方案。三种方案不能只是统一前后加减几秒；没有实质差异时，不强行生成多个版本。

故事型内容不能为了精简而删去成立所需的前因。短表达也不应为了提供完整语境版而补入无关内容。

### 3.2 切法示例

以下为演示素材，不代表实际录播内容。

| 整场时间 | 内容 |
|---|---|
| 10:00–10:08 | 观众提出挑战 |
| 10:09–10:18 | 主播说明挑战内容，并表示肯定能成功 |
| 10:19–10:27 | 实际尝试失败 |
| 10:28–10:34 | 停顿、表情反应 |
| 10:35–10:42 | 主播找补，形成第二层表达 |

| 方案 | 范围 | 依据 |
|---|---|---|
| 精简版 | 10:09–10:34 | 主播自己已经交代挑战内容，可以省略观众提问 |
| 完整语境版 | 10:00–10:42 | 保留挑战来源及完整回应 |
| 保留余韵版 | 10:09–10:42 | 省略重复提问，保留失败后的找补 |

如果主播在 10:09 只说“这个肯定行”，却没有说明“这个”是什么，精简版就需要重新判断，不能机械省略前面的挑战内容。

### 3.3 每个方案的必要信息

- 起止时间及预计时长。
- 开头第一句与结尾最后一句；没有原话时说明所依据的画面。
- 保留的事件环节和省略的内容。
- 是否需要前情字幕及其事实来源。
- 理解、断章取义和素材缺失风险。
- 选择边界所依据的句子、截图或反应。
- 自动校正前后的时间和原因。

页面说明应具体，例如：

> 比完整语境版减少 9 秒，省略重复提问；主播自己的第一句已经交代挑战内容。

不只展示“AI 建议 25 秒”。

### 3.4 边界校验

必须通过的检查：

- 起止有效，位于实际可用素材内。
- 核心行为或表达仍保留在成片中。
- 未截掉关键否定、限定条件或改变意思的上下文。
- 不以半句话开始，也不在回答尚未完成时结束。
- 跨录播分段时检查素材连续性，不能默认中间没有缺失。
- 片中删除后，前后关系仍可正确理解。

建议优化的检查：

- 尽量在完整句子、动作或自然停顿处切换。
- 音频可用时，检查是否切断字音。
- 根据素材确定反应余量，不统一固定秒数。
- 不将安静、呼吸或思考停顿一律作为无效内容。
- 不通过补静默凑时长。

规则冲突时，展示冲突及可选处理方式，由剪辑师决定，不静默回退到一个看似正常的范围。

### 3.5 编辑器交互

在现有裁剪区域增加：

**当前人工版｜精简版｜完整语境版｜保留余韵版**

各方案支持：

| 操作 | 用途 |
|---|---|
| 试听开头 | 判断进入是否自然、对象是否清楚 |
| 试听结尾 | 判断反应是否结束、退出是否突兀 |
| 播放整段 | 检查叙事是否成立 |
| 查看差异 | 标出相比当前方案新增或省略的句子 |
| 应用方案 | 确认后写入编辑稿 |
| 撤销应用 | 恢复此前的人工版本 |

切换方案仅为临时预览，不自动保存，不修改人工稿。切换事件时应清理临时试听状态，避免播放范围残留到下一个事件。

优先共用一份覆盖各方案的干净预览，通过改变播放范围比较。只有需要验证片中删除、字幕或效果后的实际表现时，才执行局部或完整渲染，不默认生成三份完整视频。

### 3.6 字幕、效果与发布包联动

所有方案保存整场原始时间。采用方案后，通过现有时间轴转换为编辑器时间和成片时间，避免重复换算造成漂移。

采用新边界时：

1. 展示哪些已有效果将处于成片范围之外，不直接删除它们。
2. 不机械平移所有效果，保留其与原话或行为的对应位置。
3. 重新检查字幕、片中删除和呼应插片。
4. 将不匹配的预览、成片和发布包标记为需要更新。
5. 提示检查封面帧、标题与开头字幕是否仍符合所选内容。
6. 保存应用前状态，保证撤销能够恢复边界、时间轴及相关选择。

必须避免“边界改了，但播放的仍是旧文件”，以及“标题对应的关键表达已经被剪掉”。

## 四、接入当前系统

| 当前能力 | 建议扩展 | 相关实现位置 |
|---|---|---|
| 候选召回 | 事件合并、关联与来源追溯 | `worker/clipper/recall.py`、`worker/scripts/recall.py` |
| 精排结论与证据 | 事件结构、前情依赖、结束依据 | `worker/scripts/rerank.py` 及对应提示词 |
| 单一边界修正 | 对多个有理由的方案分别校验 | `worker/clipper/boundary.py` |
| 素材窗口与时间轴 | 共用素材范围、转换方案时间 | `worker/clipper/edit.py`、`worker/clipper/timeline.py` |
| 后端编辑接口 | 返回方案、校验版本、应用及撤销 | `backend/.../service/EditService.java` |
| 编辑器试听与预览 | 方案切换、差异比较、失效提示 | `admin/src/views/Editor.vue` |
| 投稿与复盘 | 关联事件编号、事件版本和采用的边界方案 | 现有发布绑定与指标回流链路 |

以上为建议接入位置，不代表必须将全部新逻辑放入已有的大文件。实现时可拆分事件分析及方案生成模块，保留原边界函数供旧结果使用。

### 4.1 版本与兼容

- 保留旧候选和旧 `refined` 结果，新结构使用独立、带版本的字段或记录。
- 事件编号保持稳定，事件结构和边界方案分别版本化。
- 应用方案时校验输入版本，拒绝直接采用过期建议。
- 现有编辑稿没有事件信息时，仍能正常打开、保存与渲染。
- 重新分析不覆盖人工稿，先展示新旧差异。
- 已发布作品保留实际使用的方案版本，不随后续分析变化。

### 4.2 模型调用与缓存

- 优先复用已有逐字稿、截图和通过核验的评审证据。
- 一次事件分析可同时生成结构和多种边界方案，不为三个切法分别请求模型。
- 先合并重复事件，再进行昂贵分析。
- 设置每场事件分析数量、上下文扩展次数及调用预算。
- 缓存绑定素材、逐字稿、提示词及分析版本，输入变化后标记过期。
- 记录请求次数、缓存命中、失败原因与成本；失败不影响已有人工稿。

## 五、实施顺序

### 第一阶段：事件结构与去重

交付事件结构、证据核验、重复候选关联、事件卡片和人工修正。

重点验证：是否能找到必要前情和真正的结束点，是否减少重复审核。

### 第二阶段：多边界比较

交付连续片段的多种切法、开头结尾试听、差异比较、应用与撤销，以及预览和发布包失效提示。

重点验证：不同切法是否有真实取舍，是否减少拖动边界的次数，是否保护已有人工效果。

### 第三阶段：学习与复盘

记录最终采用的方案、人工修改的边界及原因。分别统计不同事件类型适合的切法、修改工作量和投稿表现。

人工选择不直接等同于效果标签，播放高低也不直接证明某个切法更好。比较传播或关注效果时，仍需要固定稿龄、事件去重及明确的实验条件。

## 六、验收与首轮试用

### 6.1 自动验证

至少覆盖：

- 短事件不被统一下限补长。
- 长前情不会被直接当作成片长度。
- 代词或对象缺失时提示理解障碍。
- 非幽默事件不因缺少笑点结构被否决。
- 相邻独立事件不会仅因时间近而合并。
- 同一事件多次召回后，来源仍可追溯。
- 越界时间、录像缺段和跨分段不连续被明确标记。
- 切换方案不保存，应用和撤销可以恢复原稿。
- 字幕、片中删除、效果及呼应使用同一时间映射。
- 人工编辑或输入版本变化后，旧建议不会直接覆盖新稿。
- 旧数据缺少事件和方案字段时仍可使用。
- 模型失败、预算耗尽或缓存过期不会导致现有人工稿丢失。

### 6.2 首轮素材试用

建议选择 **3 场直播、20～30 个不同类型事件**，包含搞笑、互动、观点、自然反应和安静表达，避免只用热度最高的素材验证。

| 观察项 | 记录方式 |
|---|---|
| 新观众是否理解事件 | 独立观看后复述发生了什么，记录理解缺口 |
| 必要前情是否完整 | 标记缺失或多余的句子 |
| 核心和反应是否保留 | 标记关键表达被截、反应未结束等问题 |
| 是否改变原意 | 检查否定、限定、对象与前后关系 |
| 方案是否有实质差异 | 记录只有时长不同、没有编辑理由的无效方案 |
| 剪辑师操作量 | 记录边界调整次数、调整秒数及用时 |
| 人工稿保护 | 检查切换、应用、撤销和重新分析后的稿件一致性 |

首轮用于发现问题、建立基线，不直接宣称提高播放或关注转化。根据问题分布确定下一轮重点：补前情、修结束点、改去重，或调整方案生成规则。

## 七、预期使用体验

系统先把事件、证据和可选切法整理清楚，剪辑师重点进行比较、判断和选择，减少反复拖动素材寻找起点与终点的工作。

自动化应让选择更容易解释、修改可以撤销、结果能够追溯；不能以生成了三个版本作为功能完成的唯一标准。
