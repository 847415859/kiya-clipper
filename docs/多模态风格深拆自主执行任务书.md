## 0. 执行原则与本轮授权范围

1. 目标是形成有时间证据的**内容判断、视频剪切手法、叙事编排技艺和可迁移制作配方**。可洛为主，近期优先；标题封面为辅助，不得再以报告数量和抽帧数量代替实质研究。
2. 用户要求尽可能一次自主执行，减少人工参与。无需逐阶段询问是否继续、逐条确认素材、逐句等待听写、逐条确认候选规则；按本文的自动验收、回退和预算边界继续工作。
3. **恢复机器多模态研究，不恢复被暂停的人工复核。** 旧账本的人工任务保持 `paused`；新建模型研究任务，不能把模型结论伪装成人工完成，也不能因人工任务暂停而阻塞全部内容研究。此规则替代旧文档中将人工标注设为所有研究结论唯一入口的约束。
4. 可以在独立研究工作区补充或修复研究脚本、执行本机预处理、调用已经配置且获准使用的服务、获取必要的正常公开元数据和制作素材。使用外部服务时仅提交研究必要的参考片段/帧/音频，不公开发布原视频或创建公开素材链接；无对应服务授权时走可用的本地路径，不自行开通新账户或付费订阅。
5. 原视频只读，不恢复下载、不研究回放、不读出或回显凭证、不修改生产剪辑配置、不自动发布或提交 Git。用户现有未提交代码保持原状；研究脚本可以在独立目录编写，生产功能开发仅给出有证据的接入清单。
6. 只有确实需要用户提供的凭证、预算或无法代替的权限才形成一次合并的问题清单；此时继续其他独立任务。普通内容不确定性由模型复看、交叉验证或降级处理，不能全部转交用户。
7. 本文件给出的窗口、采样和阈值是执行默认值，必须通过试跑校准并记录版本；它们不是已验证的可洛规律。不能事后改阈值只为让失败结果通过。

## 3. 成功标准与任务规模

### 3.1 第一目标：三个完整研究案例

先做完上述 3 条近期可洛作品，每条交付：

- 全片内容概括、观看回报、人物表达与前情要求。
- 覆盖全片的真实内容节点；节点数按内容决定，不能按固定 30 秒切桶充当节点。
- 关键剪切/重新构图/插入等动作的时间证据，区分切换事件和持续状态。
- 叙事节点图、必要依赖、信息揭示、反应、澄清与结束依据。
- 原话、真实弹幕、编辑评论及声音作用的区分。
- 至少一个完整关键段落的声画联合拆解，必要时补多个段落；不能只分析开头。
- 与 kiya 的迁移条件、失效条件和素材需求，不强制每条都产生可推广规则。

### 3.2 自动扩展目标

三个案例通过机器验收后，无需确认，扩到首轮 **40 条深拆**：可洛 24、次参考 8、kiya 8，包含已通过的试跑，不重复计数。独立事件不足则分析全部可用者并报告不足。

可洛 24 条目标为近 90 天 17 条、91–180 天 5 条、历史 2 条；缺额按主方案补配。内容类型、时长和制作强度必须分层；现有日期未经核实的账号单列临时排序，不伪造近期权重。

全量 952 条仍需 L1 内容研究；40 条不是替代全量完成。每批优先推进可洛近期内容，在预算和运行限制内自动处理剩余合格作品，按来源、内容节点和模态覆盖登记。达到资源边界时精确保存剩余任务，不把未处理记录标成完成。

### 3.3 完成状态分开

同时报告：输入清点、机器预处理、模型内容研究、精细声画拆解、规则候选、独立模型复核、人工确认、素材准备、系统实现、kiya 样片验证。

“模型复核通过”允许完成研究案例，不自动等于“人工确认”或“已进入生产”。没有实际样片时，制作效果验证保持未完成。

## 4. 阶段 A：修复审计与建立可信运行账本

### 4.1 修复明确的误判

问题脚本是现有研究目录的 `audit_case_asset_integrity.py`：仅读取顶层 `status`，使实际状态放在 `confidence` 或 `validation_status` 的待复核案例因读取到 `None` 而误判 `production_usable=true`。

操作步骤：

1. 保存脚本、旧审计 JSON 和报告的版本副本与哈希。
2. 按记录类型解析状态，并统一显式的研究状态字段；未知、缺失、无效 JSON、占位、空步骤、无证据必须不通过。
3. 分开输出 `research_usable`、`model_reviewed`、`human_confirmed` 和 `production_approved`；不能从前者自动推出后者。生产批准必须有明确的批准来源，默认 false。
4. 补充有意义的回归检查：缺状态、`needs_review`、嵌套状态、空配方、无效 JSON 均拒绝生产资格；明确满足研究条件的案例只能得到研究资格。
5. 重新生成修正审计，列出本次修复前后差异。不要删掉原始历史结果。

### 4.2 新建本轮账本

在 `autonomous_v1/` 建独立 SQLite 账本并导入旧任务引用，不覆盖暂停的人工作业。唯一键至少包含输入哈希、阶段、分析器版本和参数版本。

```text
eligible → capability_ready → overview_done → evidence_localized
         → multimodal_analyzed → model_reviewed → research_accepted

独立状态：retryable_failed / modality_limited / unresolved / excluded
人工状态：保持旧账本 paused，不自动写 human_confirmed
```

每步落盘有效结果后再标完成。输出用临时文件加原子替换；单条失败不终止其他可独立处理视频。阶段成功但缺少声音时只能完成对应视觉部分，不能写“全模态通过”。

## 5. 阶段 B：自动探测与选择多模态执行路径

### 5.1 选择顺序

1. 执行模型当前环境已有的真实视频、图像和音频输入能力。
2. 项目已配置且获准使用的外部模型接口。已有视觉模型配置不表示支持视频声音；须按提供方当期官方文档核对接口与输入类型。
3. 本机已经存在的可用模型与依赖，不重复下载大模型或修改系统默认环境。
4. 若没有统一影音模型，可分成视觉理解模型与音频理解模型，再用时间证据融合。ASR 和 OCR 单独不构成完整多模态路径。

不得凭模型名猜能力，不能把视频文件放进文本字段就声称已读取。运行日志保存实际输入类型、片段范围、模型标识、参数版本和调用结果状态。

### 5.2 必须执行的能力试验

从首条近期可洛视频选取一个有明显画面变化和台词的 15–30 秒段落，另取一个不同段落作为交叉检查。对原视频位置和输入路径进行程序核对。

试验要求：模型给出画面对象、至少一个实际可见变化、短句内容或听不清标记、声音类型及局部时间；每条结果注明模态。可用输入打乱、去音或只给文字的对照，检查模型是否把转写猜测冒充听音；这类对照仅验证依赖输入是否合理，不是准确率金标准。

保存 `capability_probe.json`：各模态 `supported / unsupported / uncertain`、调用证据、抽样精度和局限。自动选择通过的路径，失败则按上节切换，最多两次修复同一原因后换路径，避免重复试错。

如果全环境确实没有图像或音频理解能力，继续能完成的模态与素材准备；完整深拆标为能力不足。输出一次合并的具体缺口，不再批量生成占位案例或同义审计报告，也不假装完成。

### 5.3 资源边界

启动时从现有授权配置读取研究预算、调用限额、存储上限和服务权限，只记录非敏感配置。已存在的限制优先执行。

未指定新预算时，不把“自主执行”解释成无限额度：优先本地或执行模型已有工具；额外计费服务先运行最多 3 个主参考的校准批，不自动开始全量付费调用。校准批默认至多 30 次成功的外部研究调用（含复核），失败请求最多额外 6 次，并遵守已有更低限额；请求次数不是费用保证，若价格或单次消费无法核实，则不新增付费调用。将实测消耗和全量估算汇总后，只对确需新增预算的部分留一项输入需求，继续不依赖它的工作。

已有明确全量预算和权限时，直接按预算自动扩展，不重复询问。各批计算当前用量与下一批预计消耗；超限前保存状态，不靠继续重试越过限额。无计费调用限制不等于允许在无限循环中运行，仍需阶段任务数和失败上限。

## 6. 阶段 C：整片理解与自适应分块

### 6.1 输入与保真

优先复用已有有声代理。连续画面使用保留画幅、速度、帧序和可辨信息的代理；小字和局部对象读取原分辨率图。听音使用对应区间的实际声音，不能只传字幕。

记录代理和原视频的时长、时间原点和音视频流信息；容器时长相近不代表已验证声画同步。发现起点或速度差异时先校正映射，不能静默吸收进时间戳。

### 6.2 两种输入方式

- 原生视频/音频路径：在模型已验证限制内输入完整短片；较长作品按内容段落切块。
- 分离视觉与声音路径：对同一区间分别输入有时间标签的帧序列/连续视频与音频，再融合；缺少连续性时只能标采样观察。

默认分析块 60 秒、相邻重叠 5 秒，尽量在句尾或段落边界调整；实际受服务限制时缩短。不得把一个块当作一个事件，不得把重叠内容重复计入覆盖率。

### 6.3 第一遍任务

输出实际事件、观看回报、人物表达、必要前情、内容节点、节点依赖、开头与结束依据。不先要求“找到反转”，不靠标题决定内容。

每块完成后保留简洁上下文摘要和证据引用；全片再统一合并节点，检查跨块提问、回答、揭示、澄清与回扣。全片语义覆盖与各模态输入覆盖分别计量。

ASR 仅为索引。关键原话冲突时优先对实际音频复听；不是每句都必须先有完整正确转写才能继续分析。对不影响主要判断的无法识别词保留 `[听不清]`，不要按标题补写。

## 7. 阶段 D：关键段落与剪切手法深拆

根据第一遍内容节点，选择开场、主要看点、转折/反应、插入与结尾，以及有价值的低包装段落。第一批 3 条全部覆盖全片内容，精细区间按实际复杂程度决定，不能只看开头。

### 7.1 观察策略

- 对有原生连续视频理解的路径，先看关键区间连续声画，再为精确边界补帧。
- 帧序列路径默认先用约 1 fps 形成连续上下文；可疑切换前后补约 5 fps，仍不清楚则在小区间逐帧定位。采样率是起始设置，不代表已经连续观察。
- 边界探测、画面差分和 OCR 变化用于提出位置候选，不能自动命名“硬切”“转场”或“笑点”。
- 每次升级只处理有必要的区间，避免全片逐帧上传、无意义重复 OCR 和高成本整片重跑。

### 7.2 每个动作记录

必填：作品 ID、动作 ID、成片时间、误差范围、切前/切后上下文、触发的台词/行为、画面动作、字幕来源与动作、声音状态、注意力目标、动作进出时机、事实、作用解释、替代解释、证据路径、分析/复核来源、适用和失效条件。

明确区分：源画面变化、重新构图、叠加层出现、持续状态、全屏插入、声音变化。无法由成片确定的源删除区间、原始重排、变速比例保持未知。

### 7.3 编排技艺记录

用真实内容而非抽象词填节点图：观众何时知道什么，提问对象如何明确，预期如何形成，揭示和反应如何衔接，重复是否新增信息，澄清是否改变原意，何时结束。

图中每个节点绑定成片区间和案例 ID，依赖箭头区分“缺了就听不懂”的必要依赖与可调整的编辑建议。建议重排和假想删除属于假设，不是源素材事实。

### 7.4 声画融合

联合检查同一区间的原声、画面、字幕与插入：声音是否跨画面持续、是否打断台词、是否有阅读时间、反应停顿为何保留。实际音效名不能识别时描述听感和作用，不编造资产名称。

### 7.5 时间契约与每轮调用模板

结构化证据使用成片绝对整数毫秒 `start_ms/end_ms`，区间为 `[start_ms, end_ms)`。模型块内结果先保留原局部时间，再以块起点只换算一次；帧 seek 时间、音轨偏移、服务返回单位分别登记。报告可显示分秒，但不能丢掉精度/容差。多个块的同一动作按时间、内容和证据去重，保留原调用引用。

调用模板应由执行器填写实际 ID、时间与媒体输入，不把下面的说明原样当结果。输出尽量使用可校验结构，禁止只产出一段赞美性摘要。

**整片/分块理解提示：**

> 你在分析参考成片的内容与制作。输入含本区间实际媒体、局部转写和全片上下文；转写可能错误。先说明实际收到的模态。按发生顺序列出具体内容节点、台词/行为、人物表达、观众需要知道的前情、获得的新信息及前后依赖。标注区间、事实来源和未知项。不要预设一定好笑、反转或高能，不从标题补造台词。区分本块结论与需要跨块确认的事项。

**剪切/声画深拆提示：**

> 观察指定连续区间以及前后上下文。逐项列出可见切换、重新构图、字幕/贴图层、全屏插入和可听变化。记录开始、退出、前后画面、原声是否继续、触发的具体台词/行为，以及希望观众关注的对象。直接观察、作用解释和替代解释分栏。没有看到的原录播删除/重排保持未知；若输入仅为抽帧，写明可能漏检，不能声称连续视频已经观察。没有实际音频则声音字段未知。

**编排与制作配方提示：**

> 基于已完成的内容节点和证据动作，绘制实际信息顺序与依赖图，说明进入、铺垫、阅读/等待、揭示或表达、反应、澄清、回扣及结束中实际出现的部分。列出删掉必要节点可能造成的影响，但标为分析假设。只有证据足够才提出配方，配方包含输入条件、必须保留内容、具体动作、退出、强度、素材功能和回退。不得把“一直加特效”当风格规则。

**复核提示：**

> 先独立观察实际收到的原片段并记录事实，再逐条检验初分析。返回 supported、contradicted 或 unresolved，附时间与模态依据。重点检查台词、画面动作、声画衔接和节点依赖。不要因两个 ASR 一致就认定听对，不要求为了通过而填满未知项；必要时给出一次最小补采需求。你的结论属于模型复核，不是人工确认。

## 8. 阶段 E：模型自主复核与有限回退

### 8.1 复核不要求用户逐项确认

将关键案例交给具备所需模态的复核调用：先给原片段和明确问题，要求独立列事实，再与初分析对照。尽量不同模型；只有同一模型时用独立上下文并标 `same_model_review`，不能声称独立模型一致。

不把 ASR 文本同时喂给两次调用后，因台词相同就判为听音正确。复核日志必须保存实际收到的媒体和区间。

### 8.2 自动验收

| 检查 | 通过要求 | 失败处理 |
| --- | --- | --- |
| 时间与证据 | 区间在成片内，文件存在，引用可解析，时间换算一致 | 修复坐标/路径，重新验证 |
| 覆盖 | 全片内容节点覆盖；未知区间及各模态缺口显式列出 | 补缺口，不填假节点 |
| 剪切事实 | 所述动作有对应可见证据和前后上下文 | 缩小区间、加密帧；否则降为候选 |
| 语音与声音 | 关键台词、声音关系有实际音频依据 | 复听短段或保留未知 |
| 编排关系 | 节点使用具体内容，依赖与结束依据可回看 | 回到相关段落，不要求编造反转 |
| 制作配方 | 触发、动作、退出/回退、适用边界非空且引用事实案例 | 不生成配方，登记不足 |
| 证据等级 | 模型、人工、推断和未知没有混淆 | 修正状态，禁止升级生产 |

相同失败最多两轮定向补采/复核，避免整条反复重跑。仍有分歧就将相关结论标为 `unresolved`，隔离这条结论，继续其他节点与作品。关键内容缺失导致整条主线无法确认时，不升级该视频的完整研究状态。

### 8.3 研究案例状态

```json
{
  "research_status": "model_reviewed",
  "human_confirmed": false,
  "production_approved": false,
  "input_modalities": ["video", "audio"],
  "time_domain": "finished_video",
  "evidence_precision": "record_per_case",
  "review_method": "record_actual_method",
  "limitations": []
}
```

示例仅表示字段，不是当前已有案例状态。每条实际记录必须另有唯一 ID、区间、来源与证据。

## 9. 阶段 F：扩展样本、归纳近期风格与制作配方

完成第一条后由程序验收并自动修正，不暂停等用户确认；第一目标 3 条完成后自动扩展到第 3 节的分层样本，资源允许再推进全量 L1。

### 9.1 近期标准

严格沿用既有 90 天半衰期和 70/20/10 时间层。角色优先于时间权重：可洛主参考不变；日期未知单列，下载时间不当投稿时间；重复事件和重传版本不重复计票。

先在可洛近期样本内按内容类型和制作方式归纳，再用历史对照解释变化。不能将不同题材的作品全混合后用高频效果定义风格。

### 9.2 规则门槛

至少 3 个独立事件、来自至少 2 个日期/制作批次，且当前默认候选需至少 2 个独立近期核心支持。反例检查必须覆盖适用但未使用该手法的情况，不用“没看过”充当反例。

跨模型复核可支持“研究候选规则”，但不自动获得生产批准。若证据不足，保留有价值的单例、低包装案例和近期探索，不凑规则数。

### 9.3 制作配方

每条包括：输入内容条件、必要节点、观众信息顺序、注意力交接、具体声画动作、退出时机、强度变化、素材功能要求、无素材回退、禁用条件、可洛证据、kiya 适配和系统实现状态。

重点回答“什么时候这么剪”，不要只统计使用次数、颜色和缩放倍率。对应到候选选择、边界、自动编排、编辑契约、渲染和质检；没有开发的能力标缺失。

## 10. 阶段 G：自主准备必要制作素材

与深拆独立推进，不能因某个案例待核实而整库停工。先查项目已有素材与用户自有资源，再查正常公开、来源与使用条件明确的资源；不下载与用途无关的整包资源。

首批默认目标为 **20 件有效候选资产**，覆盖实际需要的声音提示、透明图形/贴图、短视频或动态插入、转场元素、氛围音乐等类别，不为凑数强行覆盖所有类别。若不够，交付实际数量和缺口，不能用 OCR 线索或同一素材多个格式凑数。

优先功能清楚、适合 kiya、可获得原始文件的资源。需要付费、来源不明或使用条件不明确的只存线索，不标 `ready`。允许利用现有工具自主制作简单箭头、计数、抽象背景、短提示音等替代物，登记生成方式；不要将同一程序元素的不同颜色算多个有效功能。

每项必须有：ID、哈希、原文件、类型、来源和使用条件、功能标签、预览、技术属性、状态、关联配方或明确的通用用途、适用/失效条件。`ready` 表示已通过资产入库检查，不等于任何场景都应该使用。

输出本地 `asset_library/index.html`，可筛选与试听/预览；未知素材进入 `asset_requests.jsonl`。参考作者的插入片段与最终混音截段默认仍是研究证据，不直接当作生产库。

## 11. 执行器、参数和断点要求

不要假定仓库已有可直接运行完整研究的命令。若缺少编排入口，在 `autonomous_v1/tools/` 实现最小研究执行器和适配器，复用已有工具函数；先验证试运行，再真实执行。

建议实现以下阶段：

```text
preflight → repair_audit → probe → select → prepare
          → understand → localize → analyze → review
          → aggregate → assets → validate → report
```

参数配置必须表达：输入快照、输出根、账号角色、主参考、时间层、试跑 ID、深拆目标、模型路径、模态能力、分块/补帧参数、已授权调用及成本限制、重试上限、存储限制、版本号。不要把 API Key 放进参数文件。

默认并发：视频/多模态分析 1、本地准备 1；运行稳定且额度允许再调整，不在同一小机器上同时启动大量 ASR、转码和渲染。分析完成就写输出，不等待整批全部成功才落盘。

每次上下文接近上限、工具中断、预算边界或阶段结束，写入：

```text
handoff/STATE.md             实际完成范围、质量与限制
handoff/NEXT_BATCH.json      可直接恢复的任务 ID、参数、依赖与优先级
handoff/UNRESOLVED.md        仅存真实缺口，不用其代替下一步工作
handoff/RUN_SUMMARY.json     覆盖、状态、消耗、失败与版本
```

单次交付不意味着没有断点。执行者应在同一授权下自动推进可行阶段；无法继续的边界明确报告，不能说“全部完成”后让下一模型重头开始。

## 13. 完成与停止判断

### 可标记的完成层级

- `pilot_research_complete`：3 条近期可洛整片内容研究和关键声画深拆通过机器验收，事实和解释有区分，局部缺口明示，核心结论不依赖缺失证据。
- `deep_sample_complete`：分层深拆目标完成，或所有可用样本完成且不足有依据。
- `full_l1_complete`：所有合格作品完成对应内容研究；只有机器预处理绝不能获得此状态。
- `asset_batch_complete`：真实资产按入库标准完成，报告实际数量；达到数量不代表所有配方素材齐全。
- `production_validated`：只有实际实现并完成 kiya 样片验证才允许出现。本任务默认不承诺达到该层级。

### 必须停止相关依赖的情况

真实模态能力缺失、授权/费用边界、源文件损坏、关键证据不可用。每种情况明确失败的阶段和影响范围，继续无依赖任务。不能以“需要人工”作为所有未知项的通用停止理由；也不能以减少人工为由省略验证。

> 请实际执行《docs/多模态风格深拆自主执行任务书.md》，同时读取其中列出的旧方案、检查报告和研究断点，不要只复述计划。
>

>
> 复用 worker/output/_reference_study 的 12 条机器预处理和现有近期权重；输出到其 autonomous_v1 子目录。先修复缺失状态被误判生产可用的审计错误，再实测视频、图像、音频能力。已有视觉服务不等于能听音，不凭模型名字猜能力，按官方文档与实际探测选择已有授权路径。
>
