# kiya Agent 基础开发与全流程执行计划

## 1. 给第三方开发模型的任务

在现有 kiya-clipper 工作区实现一条可解释、可续跑的自动制作链路。以一份候选状态和证据记录贯穿全程。选题编辑负责判断互动价值，剪辑师负责边界与表达，审片员负责检查实际成片，主 Agent 根据角色结果调度既有工具。先完成 Agent 基础能力和工程验收，再启动真实场次的闭环测试。

收到本文件后，先核查当前工作区和服务器交接材料，确认版本、已有改动、真实跑过的路径和未完成项。把此处的基线与实际代码对照后，从最早未完成的里程碑继续。已通过的阶段复用原结果。每批修改完成后运行对应测试，留下产物和复现命令，随后继续下一批。常规实现选择、自动重试和使用已授权的素材由执行方自主处理。只有缺少访问权限、缺少可核实的付费上界、需要修改生产账号或实际对外投稿时，才按对应边界暂停受影响步骤，继续做其余可独立完成的工作。

本轮交付终点是 **下播后自动生成带证据、可回看、可局部返修的 720p 候选成片，并写入待发布库存**。现有排期提案可继续验证。真实对照、观众反馈、自动投稿在后续阶段执行，本轮使用固定素材、模拟服务和故障注入验收。默认沿用当前发布账号设置和生产开关。

## 2. 现有能力与续做位置

| 路径或组件 | 当前仓库可见能力 | 这轮重点 |
|---|---|---|
| `deploy/monitor/kiya_monitor.py`、`worker/scripts/ops_prepare.py` | `KIYA_OPS_PREPARE=1` 下按场次入队，隔离执行粗筛、精排、Agent、投稿包和排期提案 | 接入候选级任务与状态，单条故障可恢复，整场仍能完成 |
| `worker/clipper/agent.py`、`worker/scripts/agent_run.py` | 固定编排精排、剪切、初稿、校验、渲染和质检，已有阶段级续跑 | 增加角色结果、决策路由、版本校验和定向续跑 |
| `worker/scripts/rerank.py`、`worker/clipper/video_evidence.py` | 连续音画分窗、候选时间轴、覆盖缺口、证据 ID。正式精排在有观察时使用观察文本，无观察时可回退截图。价值影子评估有独立产物 | 保留证据来源与覆盖范围，支持针对明确问题的补看，记录实际走了哪种输入 |
| `worker/scripts/autoedit.py`、`worker/clipper/arrangement.py`、后台编辑服务 | 独立待采用草稿、编排模板、必保区间和人工采用流程 | 自动初稿和返修都使用独立版本，渲染与质检绑定同一版本 |
| `worker/clipper/quality.py`、`worker/scripts/quality_check.py` | 已有结构、媒体、字幕和必保区间相关检查 | 区分技术检查与实际成片审片，接入有限返修 |
| `worker/clipper/operations.py`、`worker/scripts/publish_bili.py` | 北京时间日账本、预约与未知回执占位、排期提案、已有手动发布入口 | 复用额度账本。库存仅接收符合实际画质和内容要求的版本。发布账号与平台对账在后续验收 |

当前 kiya 配置中的正式精排是 `rerank_v6`，剪辑初稿是 `edit_v9`，连续音画配置为 `qwen3.8-omni-flash`，评分模型可由环境配置决定。下播自动制作显式渲染 720p，手动运行 `agent_run.py` 省略分辨率时默认 480p。发布入口当前能复用其他分辨率的已有成片。把生产实际配置与模型标识写进基线记录，模型升级单独验证。本轮允许复用同一模型执行多个角色，新增模型调用须能说明对应任务和预算。

## 3. 产品判断与角色权限

| 角色 | 输入 | 输出 | 可执行范围 |
|---|---|---|---|
| 选题编辑 | 粗筛候选、有效的连续音画观察、转写、弹幕、kiya 内容策略 | 选题判断、给陌生观众的必要前情、核心事件、反应与结果、证据 ID、需要补看的问题 | 给出内容判断和补看建议 |
| 剪辑师 | 已判值得剪的事件、选题理由、原片证据、允许范围、必保区间、当前草稿和返修项 | 独立剪辑版本、原片起止、必保区间、字幕与效果、拟删段和取舍理由 | 使用现有初稿和编辑工具产出版本，交给主 Agent 写入隔离工作区 |
| 审片员 | 实际渲染 MP4、版本快照、原片到成片的映射表、程序质检报告 | 通过、局部返修或待复核。问题包含时间范围、证据、严重度和建议动作 | 检查实片，提出返修建议 |
| 主 Agent | 候选状态、角色结构化结果、已有产物、预算、磁盘与任务限制 | 路由、工具调用、状态迁移、阻塞原因和可恢复记录 | 按白名单执行，校验角色输出、版本和费用，并持久化结果 |

角色是同一编排内的职责边界。优先将角色判断接到现有精排、初稿和质检输出，评估哪些情况确实需要额外模型请求。模型输出只表达判断和建议。执行器依据已定义的动作类型构造参数，并校验源文件、工作目录、权限和数值范围。

### 选题与品牌

- 长期形象是亲近、可爱的虚拟主播。提高反差、出丑、抽象、灵机一动的优先级，保留腻人、温馨、有趣等能体现真实互动的片段。
- 优先判断观众是否能理解触发、转折、kiya 的反应和结果。弹幕热度、视觉效果和反差标签都只能作为线索。敏感、隐私或可能让人误解主播的话题进入复核。
- 素材中出现其他角色时，包装和编排仍需清楚交代 kiya 的角色。生成封面时，如已有经选定的 kiya 主形象参考，优先使用该参考及一致的主体定位。身份、素材来源或标题表述存疑时留待复核。
- 蒸馏规则以候选 Prompt 或策略版本接入，记录适用条件、反例、来源及版本。使用独立 kiya 场次验证适配性。研究用参考素材与本项目的生产素材分别管理。

## 4. 状态、证据和版本约定

优先扩展现有 `agent_run.json` 或配套的候选状态文件，保留旧字段和读取行为。以下为语义契约，字段命名可结合现有系统落地。每一步先写状态和执行标识，再调用工具，完成后校验实际产物并提交新状态。状态文件采用同目录临时文件原子替换。并发执行时使用同一任务锁或事务约束，按实际环境验证。

| 状态 | 进入条件 | 合法下一步 |
|---|---|---|
| 已发现 | 粗筛有候选且能定位原片 | 选题评审 |
| 待补证据 | 有潜力，但当前证据无法回答影响选题或剪点的问题 | 复用或补看，再回到发起补看的角色。不可取得时转待复核 |
| 值得剪 | 核心事件、关键反应与结果有可追溯证据 | 生成独立剪辑草稿 |
| 待审片 | 某一草稿版本已渲染并完成程序质检 | 入库、局部返修或待复核 |
| 待返修 | 审片给出可执行、带区间的修复项 | 生成下一版，仅重跑受影响步骤 |
| 暂停续跑 | 磁盘不足、预算不足、录播暂缺、工具超时等可恢复阻塞 | 条件满足后回到原步骤 |
| 待复核 | 版权或隐私不清、说话人归属不清、关键证据无法取得、修改存在语义风险等 | 保留记录和可回看产物，等待复核结论 |
| 已入库 | 内容审片通过、媒体检查达标且版本匹配 | 输出待发布库存和排期提案 |
| 已放弃 | 确认价值不足、重复事件，或无法剪成完整且诚实的片段 | 保留原因和相关证据，正常结束该候选 |

### 最小状态记录

| 字段组 | 必须记录 |
|---|---|
| 标识 | 主播、房间、场次、候选原始序号、事件 ID、状态、流程和数据版本 |
| 决策 | 角色、时间、判断、理由、证据 ID、明确的下一动作、被阻塞的步骤 |
| 证据 | 源文件和版本、原片全场秒、片段相对时刻、来源模态、证据内容、确认方式、覆盖缺口、可回看位置 |
| 草稿与成片 | 当前版本及父版本、采用的证据版本、剪辑配置摘要、实际媒体信息、成片到原片映射、质检报告和必要时的文件指纹 |
| 执行 | 步骤唯一标识、请求和尝试标识、开始完成时间、失败类型、实际产物路径、重试条件、Prompt 与模型版本 |
| 账本 | 缓存命中、成功或失败的调用、使用量、费用预留、已对账费用、状态未知的预留 |

### 证据与缓存约束

- 原片全场秒、文件内秒、成片秒显式区分。遇到跨文件断点、缺音轨、错位、单位异常或错误的时间范围，记录实际覆盖和缺口。模型估计时间可作为候选锚点。需要精确剪点的时间以原片音画和可验证的时间戳核对。
- 补看任务包含候选、问题、目标模态、目标区间、触发原因和已有证据。例如「确认 95.7–96.32 秒的回应有没有说完」。按缺口拼出最小区间。优先复用本地相邻帧、原声和现有证据，再考虑付费请求。
- 缓存键包含素材身份及版本、区间、模态、参数、模型和 Prompt 版本。缓存命中须能指出源记录。源文件或关键配置变化时，只使依赖它的步骤失效。媒体实物和状态快照同时校验，避免“状态已通过，文件已换掉”。
- 相同场次中被多个粗筛候选命中的同一互动，可共享事件 ID 和证据。重叠仅作为去重线索，前因、转折和反应不同的相邻互动分别保留。

## 5. 开发里程碑

### 批次 A0　锁定基线和工作区

1. 记录 Git 提交、已有未提交改动、运行环境、配置来源、当前生产开关和 API 预算来源。保留已有改动和人工编辑。
2. 用固定素材或最小可复现场次跑出当前流程的基线。至少包含一条有明确前因和反应的候选、一条缺证据的候选及一条低价值候选。
3. 记下每步的入口、输入、产物及终止条件。标注真实音画、测试夹具、模拟模型和正式结果。现有录播中合适的片段可作工程夹具，真实效果评测留到后续独立场次。
4. 输出基线及差异列表。若短期无法连接服务器，可在本地完成其他批次的实现与模拟验收，并明确服务器待验部分。

### 批次 A1　角色契约、候选决策和断点续跑

1. 实现角色结构化输入输出，将精排结果归档为选题判断，将初稿和质检归档到独立的草稿版本。选题价值、边界完整度、发布资格分别保存。结果缺少必填字段或证据时转补看或复核。
2. 增加候选级状态路由。确定性规则控制哪些状态可调工具、必须校验哪些输入、产物能写到哪里。精排成功的候选即使与同场失败候选并存，也能继续制作。
3. 采用场次与候选一致的标识。锁定同一候选的当前版本，同步或异步任务结束时核对输入版本，旧结果只能做历史记录。重启、重复触发或两个进程争用时只保留一个有效执行者。
4. 每条候选提供一条易读摘要，例如「扫码反转值得剪。后置提醒和 kiya 的回应有证据，结尾原声待确认。下一步只补听回应末尾」。技术日志保留细节，摘要必须可链接到原始区间或产物。
5. 验收重点包括有效候选入制作、证据不足不误判为低价值、低价值正常结束、部分失败保留已完成项、进程中断后恢复、重复入队不会重复付费或覆盖草稿。

### 批次 A2　按证据缺口定向补看

1. 定义可识别的问题类型。至少包含前因缺失、人物归属不清、关键画面缺失、反应被截、原声和字幕时序不一致。
2. 为问题类型生成明确的模态和目标区间。从不可用区间中扣除无原片的部分，从已有证据中扣除仍有效的范围。各区间以原片时间保存。同时保留视听对应关系。
3. 先本地取证。只在本地结果不足以回答问题时调用对应模型。初始建议每候选最多两轮付费补看，每轮只处理会改变剪辑决定的问题。上限可配置，按预算守卫和素材边界执行。回答已明确、没有新证据、模型重复输出或触及额度时停止。
4. 连续音画有效时，正式评分使用观察结果。截图回退、独立影子评估和无观察状态各自记录。若截图能证明画面存在但无法证明谁在说话或原声结尾是否完整，保留对应缺口。
5. 验收用同一候选验证前后定向补看、跨录播分段缺口、转写误听、时间单位异常、已有证据缓存命中和预算不足时续跑。检查取证范围与成本记录。

### 批次 A3　独立草稿、实际审片和局部返修

1. 初稿和返修均使用独立版本，沿用待采用草稿或隔离场次工作区。产物包括关联的候选、证据、版本和实际成片。人工采用沿用现有修订检查。
2. 渲染使用固定的草稿快照。切点用原片时间，字幕和特效需正确映射到成片时间。关键对白、必要画面、观众触发和 kiya 反应等必保项贯穿草稿、渲染计划、质检。核对衔接处的音画，不跨越原片缺口代替真实素材。
3. 分两步审片。程序检查实际解码、画质、音轨、字幕读速、原片映射及必保区间。语义检查使用实际 MP4 的关键片段，核对陌生观众是否能理解、主播反应是否完整、字幕和效果是否影响阅读、标题是否夸大。
4. 建立问题到动作的映射。简短字幕来不及读可拆句或借用安全时长，特效遮挡可移位或移除，末句被截可按核实原声延后。前因不清先补证据再决定扩边界或加简短前情。涉及事实改变或证据不足时交复核。
5. 建议每候选最多两轮自动返修。返修后复查原问题以及受它影响的语义、字幕和必保项。局部变更优先复用未受影响的精排、选题、素材和缓存。新的风险或同一问题反复出现时，保留双方差异以及最后一个可回看的版本。
6. 验收用固定样本覆盖 480p 预览与 720p 成片并存、仅有 480p、末句被截、字幕过快、遮挡、跨段缺失、修订冲突。核对人工正式脚本的文件摘要在自动生成和返修后保持一致。

### 批次 A4　预算、磁盘、库存和运维

1. 每次托管付费调用前，在统一账本按北京时间自然日预留整数分。每天最多 5000 分，覆盖重试、结构修复、供应商状态未知和进行中请求。缓存命中不产生新预留。ASR 和相关 OSS 操作也需要可核实的上界。查不到真实费用时保留预留。已对账费用单独记录。流程外人工费用只有在接入同一账本后才计入综合限额。
2. 启动渲染前按实际文件系统检查录播、源视频、临时文件与成片的剩余空间。优先给在录素材留空间，空间不足时暂停新的分析或渲染，并提示哪个目录、需要多少余量。临时清理仅限明确归属的作业临时文件。原录播按现有归档与核验流程处理。
3. Agent 默认制作 720p。使用实际媒体探测结果判断能否入库，文件名只做索引。入库项绑定指定成片、草稿、质检和投稿包。只有低清预览或成片版本不匹配时回到制作或复核。现有手动发布的兼容行为交由独立配置维护。
4. 运营摘要记录每场的候选数、建议放弃原因、证据缺口、返修次数、入库数、停机原因、耗时及成本。重复告警聚合。保留现有排期提案入口，库存原件在暂缓排期时仍可复用。
5. 验收包含接近 50 元、两进程争抢额度、超时无 usage、跨日自动解锁、磁盘不足、质检结果过期、作业恢复以及库存重复提交。

## 6. 基础阶段验收表

| 场景 | 通过标准 |
|---|---|
| 通常成功路径 | 在隔离场次从粗筛走到依据齐全的 720p 成片、质检和库存。每条推荐能定位触发、反应及原片位置 |
| 有价值但初稿有问题 | 保留选题结论，产生版本化局部返修，修完后重新审片 |
| 无法补齐证据 | 留下未解决问题和已检查范围，候选待复核，同场其他候选能继续 |
| 重复触发或进程崩溃 | 继续已提交的状态。已有有效产物被识别，重复任务不额外调用模型或产生第二份库存记录 |
| 模型超时或账单未知 | 记失败与预留，按预算和重试策略处理，日志能查到对应请求 |
| 真实成片与审核不一致 | 拦截版本或媒体身份不匹配的结果，复用仍然可信的上游工作 |
| 自动制作与人工操作并发 | 自动草稿独立保存，人工采用前校验修订，冲突有日志且可恢复 |
| 兼容旧流程 | 老格式场次、人工编辑、480p 预览与手动投稿仍可按原入口使用 |

### 一条样本的执行顺序

1. 从固定录播准备候选和现有证据，记录原片身份。让选题编辑确认「前置扫码失败 → 观众提醒 → kiya 反应」是否有编辑价值。
2. 在夹具中保留一次可核实的末句证据缺口，确认实际只补听缺口区间。恢复后确认此前成功的精排结果和视频证据仍被复用。
3. 生成独立草稿及预览。用一个有意过早的结尾验证审片员能指明问题，返修只修改末尾与相应字幕。回看返修前后，核对触发与必保回应。
4. 渲染 720p 并检查媒体。用相同输入再运行一次，验证不会重复调用已完成步骤或产生第二份库存记录。
5. 在另一条候选注入无权读取或无法补齐的片段。检查它能进入待复核，同时第一条仍能独立入库。保留两条记录作为交付示例。

## 7. 后续闭环阶段

### B1　独立 kiya 场次对照

基础验收通过后，从未参与蒸馏、规则设计或工程夹具的 kiya 录播里选样。对同一份素材保留现行流程与新流程的结果，记录召回、有效事件完整度、字幕和原声问题、每条成本、耗时与人工返修。选取系统推荐、低分但可疑、待复核三类片段回看。需要外部观众反馈时记录实际参与者和观察结果。由真实问题驱动 Prompt 更新，版本可回退。

### B2　排期与投稿

使用设置页登录的指定账号，校验 UID 和登录状态。接入能覆盖手动稿、当天定时稿、审核中稿及未知回执的完整账号数据，确立稳定稿件 ID 和可信记录时间。按北京时间每天公开数量最多 3 条计算，明确每种稿件预计占用哪一天。Agent 结合内容时效、近期题材和当天名额选择发布时间，允许整天空发。提交前重新核对账号、名额、实际成片、风险和重复情况，提交后对账。未知回执继续占位，平台记录确认后再决定是否重试。对真实投稿的验收应先完成模拟、影子排期和账号只读核验，再按既有授权启用生产提交。

### B3　反馈和持续蒸馏

按漏召回、选题误判、前因过短或过长、反应缺失、发布包装等原因归档反馈。蒸馏素材按已确认的 500 天窗口更新，持续复用已有观察、分析和案例。把新增规则写成有适用条件与反例的 Prompt 候选，在独立场次对照后再采用。把观看反馈与人工编辑反馈对回实际草稿、成片、规则版本和素材。

## 8. 第三方交付与停止条件

按 A0 → A1 → A2 → A3 → A4 实现。A 阶段默认维持隔离运行。能独立推进的工程工作在其他步骤阻塞时继续，避免将整批停在单一缺项上。提交以下材料：

1. **实现与配置**：变更文件、已有组件复用点、角色及状态接口、默认参数说明、日志和产物落点、兼容说明。
2. **复现与回退**：如何从固定素材启动、如何重启续跑、如何查看某条候选的证据和成片、如何关闭新路由及继续读旧状态。列出测试命令和运行结果。
3. **验收产物**：至少一条可回看的完成样本和一条真实表现为待复核或暂停的工程样本。附版本状态、角色决策、补看证据、返修前后、媒体探测结果和费用账本。模拟素材和模拟回执清晰标记。
4. **进度说明**：逐批给出已实现、已验证、阻塞项及续跑入口。列出付费请求数量及金额口径、被暂停的任务、需要服务器验证的行为和下一步建议。

以下情况暂停对应动作：原片或必要证据无法读取、预算上界未核实、磁盘无法安全承接任务、账号或回执不明确、实际投稿权限缺失。日志说明发生了什么、已保留哪些可用产物、满足什么条件后从哪一步继续。A 阶段结束时交付可运行的自动制作基础及其工程证据，再进入 B 阶段。
