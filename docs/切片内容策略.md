# 切片内容策略（kiya-clipper）

修订日期：2026-11-17。本文定义内容目标、选题、剪辑、包装与复盘方法，与 [技术方案](技术方案.md) 的实现说明互补。

本文中的状态分为：**阶段决策**、**待验证假设**、**当前已实现**、**待开发方案**。文中的新增字段和评分原型尚未接入生产代码，不能据此认为系统已经按新策略运行。

## 一、目标与判断口径

### 1.1 当前阶段：涨粉优先，保留 60% 的方向

**阶段决策**：当前以切片号涨粉为主，兼顾传播、老粉关系与主播形象。为使「60%」可执行，本文建议先按**可发布内容的选题配额目标**解释，首轮复盘确认；它不是评分中可爱维度的占比，也不是承诺涨粉贡献达到 60%。

例如滚动观察 10 条合格投稿，其中约 6 条优先面向第一次认识主播的观众，另外约 4 条兼顾传播和老粉共鸣。探索性选题可以包含在这 10 条内；不为凑配额发布不合格内容。五维权重用于候选排序，与发布配额分开管理。

必须区分两个关注目标：

- **切片号关注**：当前主目标。单条稿件能取得直接关注数据时，才计算该稿件的关注转化。
- **主播关注 / 直播间回流**：辅助目标，单独记录。不能把切片号涨粉当作主播涨粉，也不能把账号同期净增全部归因于某条切片。

可用的单条转化口径为：同一周期的稿件归因新增关注 ÷ 稿件播放 × 1000。缺少归因或播放分母为零时不计算。

若暂时没有可信的单条关注归因，先验证「新观众能否看懂」「是否记住主播的一个特点」「是否看完」，公开互动数据只作辅助观察，不把「已关注」评论当作真实新增关注人数。

### 1.2 内容价值与排序特征分开

切片的价值不只有「好笑」，但价值也不能直接等同于萌系词或强情绪。

| 内容目标 | 观众得到什么 | 观察问题 |
|---|---|---|
| 传播 | 一个值得分享的事件、观点或反差 | 分享时能否一句话讲清看点？ |
| 涨粉 | 认识并喜欢主播的具体特点 | 看完能说出她哪里特别吗？ |
| 关系维护 | 对共同经历、互动与情感的回应 | 老粉能否得到有内容的共鸣？ |
| 信息 / 情绪回报 | 新信息、清晰表达、放松、治愈或情绪释放 | 不靠包装，素材本身给了什么回报？ |

这些是运营目标。`cute / contrast / charm / unique / funny_strength` 是待验证的排序特征，并非五种效果的直接测量，更不等于真实涨粉概率。

### 1.3 人设与真实表达

「温柔外表与意外反应的反差」可以作为选题假设；「窝囊」「傻 V」等表述只能在主播可接受、素材语境成立时使用，不应成为所有片段的固定解释。

人物形象不能由单次失态定义。保留能改变原意的前后句、否定词、玩笑提示和对他人的回应；字幕、标题与效果均不能替素材编造事实。假聊天或伪 UI 必须让观众能够辨认是剪辑演绎。

## 二、选题评分与证据

### 2.1 保留当前五维权重，标记为实验假设

| 维度 | 初始权重 | 含义 |
|---|---:|---|
| `cute` | 0.20 | 可观察的可爱瞬间与自然表达 |
| `contrast` | 0.30 | 有证据的预期与实际落差 |
| `charm` | 0.25 | 具体表达、选择或行动体现的性格魅力 |
| `unique` | 0.15 | 容易识别、又不必先懂旧梗的主播特色 |
| `funny_strength` | 0.10 | 好笑的强度，连续值 0–1 |

保留「反差为主、魅力次之、萌点兜底」的方向，但权重是人工假设，不是数据结论。新增连续字段使用 `funny_strength`，**不复用历史布尔字段 `funny`**。旧 `funny` 继续服务旧版精排，便于比较和回退。

不把「不可爱」等同于质量差。严肃、真诚、信息充分的片段仍可有较高的其他价值；严肃片段在 `cute` 上低分不意味着应淘汰。

### 2.2 每个分数必须有证据，缺失不记零

| 维度 | 可用证据 | 容易误判的情况 |
|---|---|---|
| 萌点 | 一句原话、一个动作或表情及其时间 | 只看到「喵」字就认定语气可爱 |
| 反差 | 预期对应的原话 / 行动、实际结果、二者时间 | 用「VTuber 应该温柔」这样的先入印象制造反差 |
| 魅力 | 对他人的具体回应、表达方式、选择或行动 | 只写「很真诚」「让人喜欢」，没有可复核行为 |
| 专属度 | 不依赖旧梗知识也能记住的表达或性格 | 只有老粉知道的称呼堆叠，路人无法理解 |
| 好笑强度 | 笑点机制及对应事件 / 语句 | 把大声、尖叫、弹幕多直接当作好笑 |

每个高分至少能对应一条可复核依据：来源、时间、原话或画面描述，以及为何支持这个判断。弹幕是已有直播观众的反应，不代表陌生观众也会有同样感受；「路转粉」可作证据线索，不能直接计作关注转化。

当前精排输入主要是原话转写、弹幕和截图，**没有把原始音频直接交给精排模型**。因此软糯、撒娇语调、声音治愈等判断，没有音频证据时应标为未知或交给人工试听，不能声称已经听见。

分数锚点先统一为：0 = 有充分证据表明该特征弱；0.5 = 特征明确但不是主要看点；1 = 特征强且贯穿核心回报。无法判断用 `null`，与真实低分分开。锚点要逐渐补充经人工确认的正例、反例和边界例。模型自报的 confidence 也不是已校准的真实正确率，需要与人工复核结果分开记录。

反差中的「主播自己立下预期」通常证据更清楚，但不再机械加 `0.2`；否则同一条证据会在特征判断与额外加分中重复计算。

### 2.3 不做互斥赛道，保留轻量标签

**阶段决策**：不建立一套必须互斥的运营赛道，也不按「爆了以后属于哪类」解释所有内容。

但排序、剪辑与复盘仍需要标签：一个片段可以同时包含反差、互动、萌点；`main_value` 仅表示本次主要编辑目标，`types` 作为多标签，`type` 保留给旧流程。标签不被当作天然的传播预测器。

分类有重叠不是取消分析标签的理由。后续汇总要说明多标签样本会重复出现，不能把各类数量简单相加当作独立样本。

## 三、候选召回与内容分流

### 3.1 先解决没找到，再优化排序

只改精排权重，无法找回粗筛根本没有送进来的安静片段。现有峰值召回擅长弹幕密集、响度突增和画面变化，不能代表所有有价值的素材。

**待开发方案**：保留峰值召回，增加独立的候选来源。

| 来源 | 用途 | 控制方式 |
|---|---|---|
| 峰值候选 | 强反应、反差、整活 | 保留现有方法 |
| 原话语义候选 | 具体互动、真诚表达、微事件、萌点线索 | 关键词只作触发线索，再核对完整语境 |
| 非峰值探索窗口 | 发现没有已知关键词的安静好内容 | 每场固定抽少量窗口，避免只验证既有偏好 |
| 人工时间标记 | 主播、运营、剪辑师主动提供候选 | 与自动候选进入同一审核标准 |

先设每场候选数与模型调用预算。例如增加 5–10 个非峰值窗口进行小规模试验，再按命中率和成本调整；这不是固定最优数量。重叠窗口、同一事件与同一笑点先合并，避免一场热闹内容占满候选。

不要用「响度平稳 + 语速适中」直接定义温柔或治愈。真正新增声学判断前，需要可验证的特征与人工样本。检索前后文可以扩至 120–180 秒，但这是**理解素材的范围**，不意味着最终视频也要这么长。

评估召回时，人工抽查非峰值窗口，记录有价值片段被哪个来源找到、哪些仍被漏掉，以及每找到一条合格素材所需的审核时间。

### 3.2 分开处理禁止、可修复与低价值

| 分流 | 例子 | 处理 |
|---|---|---|
| 隔离复核，未通过不能自动发布 | 高风险、明显误读、主播禁区、关键原话无法核实 | 保留素材与证据，人工决定；不由模型静默删除 |
| 可修复候选 | 缺前情、开头拖、起止不完整、字幕识别有疑点 | 补真实前情、调整边界、试听校对后再评估 |
| 内容价值不足 | 只有服务性欢迎 / 谢礼、没有独立回报的重复内容 | 降低优先级；保留原因供抽查 |
| 正常候选 | 有明确回报且可独立理解 | 进入排序与编辑 |

`fail_reason` 是诊断信息，不能简单理解为「非空就删除」。`need_context`、`weak_hook`、`incomplete` 往往有修复空间；`read_sc` 也要区分纯念留言与具有具体互动回报的内容。

新价值策略下，`not_funny` 不再等同于「不值得发」。需要改为「主要目标没有成立」或由多维证据说明为何无独立价值。保留失败候选抽查，防止新策略的漏检被隐藏。

## 四、结构与剪辑

### 4.1 结构围绕回报，不强求每条都有爆点

| 编辑目标 | 基本结构 | 检查重点 |
|---|---|---|
| 强反差 / 搞笑 | 必要预期 → 事件 / 笑点 → 真实反应 | 预期能懂，结果不被包装抢走 |
| 金句 / 观点 | 必要问题 → 核心表达 → 一点解释或反应 | 不用脱离语境的断句制造观点 |
| 萌点 / 治愈 | 可理解的情境 → 自然表达或微事件 → 完成与余韵 | 可以没有高峰，但要知道为什么值得看 |
| 互动 / 情感 | 互动缘由 → 回应 → 对方或主播的后续 | 不把真实关系剪成另一个意思 |

20–60 秒、60–120 秒等只作为试剪参考，最终时长由内容的最短完整表达决定。安静内容也可能很短；不能因为叫「氛围」就自动延长。较长内容必须持续提供新信息、互动或体验。

### 4.2 起止点：修复一处不等于修完整条链路

当前 [boundary.py](../worker/clipper/boundary.py) 的 `s0 = min(s0, p - setup)` 确实可能把精排明确给出的起点提前。原先「只在没有 start 时才用 setup」的方向可以保留，但不能直接照抄原文的替换片段上线：

- `min(p - 20, p - setup)` 在默认 `setup=8` 时仍总是选择提前 20 秒，没有表达清楚想要的默认策略。
- 当前函数还有最短时长补足、整句扩展、句首对齐和最长时长截断，都可能再次改变起止点。
- 模型给出的时间可能无效、超过素材或切掉必要信息，不能无条件信任。

**目标约束（待实现）**：先验证模型时间与证据；有效的明确起点优先，仅作必要的整句对齐。缺失起点时，才按编辑目标应用默认前留。最短时长补足不应重新推翻已验证的短内容边界。各次调整都记录原因和前后时间，人工能回看。

测试至少包含：明确起点、无起点、短萌点、长前情、跨句、首尾越界、接缝与删除段。还要区分函数默认值和实际调用配置：函数签名默认 `min_len=30`，精排脚本会传入配置，而当前 `config/kiya.yaml` 的 `min_len=20`。不能据函数默认值断言所有片段都会补到 30 秒；应验证实际生效的最短时长是否破坏短内容边界。

### 4.3 开头钩子：先给具体信息

「前 3 秒」用作检查窗口，不再声称它必然决定大半完播。下面是可测试的方法，不是对所有片段通用的规则：

- 第一句就交代事件起因或互动对象。
- 必要时用一句真实、具体的前情字幕，降低理解成本。
- 倒叙只在不改变事实、不会破坏核心回报时使用，并检查重复感。

「她接下来做了件离谱的事」信息量低，也容易和大量视频同质化。若原素材确实存在「她刚说绝不翻车」这样的承诺，可直接建立明确预期；没有这句话就不能编出来。萌点内容也可以直接从自然表达开始，不必强加悬念。

### 4.4 萌点模板：减少干扰，保留原声

**待开发**：`prompts/edit_cute_v1.md`，当前仓库没有这份模板。选择模板不能只看一个低置信度的 `main_value`，还需要维度证据与人工可切换入口。

| 项目 | 萌点试验模板的起始约束 |
|---|---|
| 效果 | 整条尽量 0–3 个，验证有帮助才保留 |
| 运镜 | 轻推近，初始可试 1.0–1.15，避免遮挡动作或表情 |
| 旁白 / 贴图 | 不替观众下结论，不盖住核心表达 |
| 音乐 | 原声优先；有背景音乐时核对压低、音量与实际听感 |
| 切点 | 自然停顿、动作或语义完成处，不在表达中间硬断 |
| 时长 | 内容完成即结束，不为了满足模板秒数补静默 |

以上数值是模板实验参数，不是质量标准。搞笑内容同样不应默认「花字越多越好」。已实现的片中删除、原话校对、干净预览、局部试渲染和手机宽度复看，作为两种模板共同的验收工具。

## 五、标题与封面

### 5.1 标题先验证承诺与兑现

每条先生成 2–3 个不同角度的标题，再核对：具体事件是什么、路人是否看懂、标题承诺是否在视频里兑现、是否损害人物原意。标题与封面负责不同的信息，避免把同一句话重复两遍。

悬念、反差、语录、情绪等只是表达方式，不是必选公式。「不剧透」也不是绝对要求：有的内容适合展示结果，让观众好奇过程或表达方式。不要把「她破防了」一律判错，也不要把「她做了件离谱的事」一律判优。

自嘲、贬称或圈内称呼需要核对主播接受程度及陌生观众的理解，不默认使用「傻 V」等标签。

### 5.2 封面已经能叠字，缺的是选择依据

当前发布链路已有封面文字、主题样式和多版本能力，见 [publish_pack.py](../worker/scripts/publish_pack.py) 与 [publish.py](../worker/clipper/publish.py)。因此不能再写「当前只有 cover_time，缺大字标题」。

待补的是：精排结构化输出 `cover_text`、选择依据、真实素材时间以及手机宽度可读性检查。2–4 字可以作为一个试验版本，不是所有封面都必须遵守的限制。

选能表达真实情境的帧，不总是最夸张的表情。封面若让观众预期的是另一件事，即使获得点击，也不能算内容策略成功。生成式封面不能被当作真实直播截图证据。

「封面决定点击率的一半」没有本账号证据，删除该定量结论。

## 六、发布与供给

**阶段决策保留**：先聚焦 B站，不增加多平台竖屏重排工作；正式栏目和合集暂缓。可以用轻量内部标签记录重复出现的内容主题，不额外承诺固定栏目产量。

晚上 19–22 点只是待测试时段，不写成已证实的平台或本账号最优时段。选择少量可持续的时段，在相近内容和一致观察周期下比较，不同时修改所有发布变量。

发布频率由合格库存、剪辑产能与素材重复度决定。一场直播可以没有合格切片，也可以有多条；不同时承诺「一场一条」与「一场 3–5 条」两套固定目标。同一事件的多个候选先去重，避免把同一段素材换包装当作不同选题。

发布前确认：原话和字幕一致、前情够用、标题封面兑现、人物形象与事实成立、声音与手机观看通过。任何自动推荐都不等于已经完成人工发布验收。

## 七、数据回流与实验

### 7.1 指标、来源与缺失状态

| 指标 | 用途与口径 | 缺失时怎么办 |
|---|---|---|
| 播放、赞、币、收藏、分享 | 公开统计，按固定稿龄比较 | 保留缓存并注明；失败不写零 |
| 完播 / 留存 | 能取得创作中心单条数据时手工录入，记录时长与周期 | 标未知，不由播放或点赞推算 |
| 单条新增关注 | 有明确单条归因数据时计算每千播放关注数 | 只记录账号同期变化，注明不可归因 |
| 点击率 | 需要同来源、同周期的曝光和点击数据 | 没有曝光分母就不声称某标题提高了点击率 |
| 评论内容 | 发现误读、人物记忆点和内容需求 | 作为定性材料，不代替关注或留存人数 |
| 审核成本 / 返工 | 检查系统是否减少人工寻找和修剪时间 | 保留人工记录，不只看模型分数 |

当前项目已有公开统计读取、手工 `completion / followers` 字段及类型汇总。手工数据必须注明来源、时间范围、是否单条归因与单位；无法取得时不伪装为自动采集能力。

投稿列表受限与单条 BV 查询是不同路径。绑定数、拉取成功数、有效分析样本数分别展示；同一 BV 多次读取或同一切片重投，不能被当成多个独立选题样本。

### 7.2 先统一观察周期，再讨论哪类好

初始可记录发布后 24 小时与 7 天快照，作为本项目的观察规则，之后再调整。不能把新发 1 小时的视频与发布 1 个月的视频累计播放直接比较。历史只有当前累计值时，注明无法回填过去快照。

至少保存：素材身份（场次、候选序号、整场起止）、BV、是否重投、发布时间、成片时长、主要目标、多标签、标题 / 封面版本、策略与提示词版本、数据采集时间及缓存状态。

现有 [type_stats](../worker/clipper/memory.py) 使用中位播放与互动率，启动门槛针对总有效样本数，**不是每类都已经有 5 条**。文档原来的「每类 5 条才有统计意义」不能作为统计保证。

每组都应展示样本数与离散情况。5 条可以开始描述观察，不足以自动证明某种风格或权重有效。低样本、稿龄不一致或数据大部分缺失时，仅作案例复盘，不给稳定优劣结论。

### 7.3 一个结论不能跳过中间环节

| 观察 | 可能的其他解释 | 优先动作 |
|---|---|---|
| 某类播放高 | 标题、封面、稿龄、热点、流量来源不同 | 核对比较条件，先不自动调内容权重 |
| 点击高但完播差 | 包装承诺与素材不符，或开头理解成本高 | 检查兑现与开头，不继续强化标题刺激 |
| 看完但关注弱 | 事件有趣，但主播特点或账号定位不清 | 检查看完后能记住什么，补可靠的归因数据 |
| 模型高分但人工常否决 | 锚点、证据或召回偏差 | 修评价标准与样例，不先加更多特效 |

不能直接从「破防播放高」推出「contrast 权重该上调」。模型分数、人工判断与发布结果需要分别记录，避免只发布模型喜欢的内容，再用这些内容证明模型正确。

### 7.4 小规模探索与暂停条件

先设一个发布批次作为观察单位，固定主要评分版本；同一批次尽量只验证一个核心变化，例如新增非峰值召回或采用更克制的萌点模板。保留一部分旧策略内容作参照，探索配额包含在现有选题配额中。

不同视频之间的比较会受到素材差异影响；同一稿件改标题后的前后比较也受流量阶段影响。没有随机分组或可靠控制条件时称为探索比较，不包装成因果 A/B 结论。

每轮记录：假设、样本选择、预算、主要指标、内容质量护栏、复盘时间和停止条件。暂停条件包括事实误读、观众明显困惑、主播不接受的形象表达、审核成本不可承受，或主要指标持续没有改善。

2–3 个月可以作为复盘日程，但不是到期自动获得足够样本。是否调整权重取决于样本与证据质量；小样本先修复可观察的编辑问题。

## 八、字段与兼容方案（待开发）

### 8.1 新旧结构必须可区分

| 字段 | 建议结构 | 兼容说明 |
|---|---|---|
| `value_schema_version` | 整数，首版为 1 | 无此版本的旧结果走原评分逻辑 |
| 五维值 | `cute / contrast / charm / unique / funny_strength`，0–1 或 null | null 是未知；不将历史 funny 布尔值当强度 |
| `value_evidence` | 来源、时间、引用、支持哪个维度及理由 | 与旧 evidence 并存；不冒充未提供的音频证据 |
| `main_value` | 主要编辑目标 | 用于模板建议，不是互斥内容赛道 |
| `cover_text / hook_caption` | 可选文本，附证据引用 | 只有事实成立时输出；空值不是失败 |
| `title_options` | title、style、why、evidence_refs | 保留旧 title_candidates 字符串列表，不原地改成对象列表 |
| 策略与评审版本 | strategy_version、prompt_version、rubric_version | 使新旧判断、人工标注和回流结果可追溯 |

当前 `RerankOut.title_candidates` 为字符串列表，发布与页面也按字符串使用。把该字段直接改为对象列表会破坏下游，必须新增字段并同步消费者。

### 8.2 评分原型与边界

原方案存在三个问题：旧结果的 `funny=True` 会被当成数值 1，使旧结果无法正确回退；全零新分会错误回退到旧 `score`；保留 `not_funny` 惩罚会把萌点内容再次降权。

下面展示五维评分核心。当前代码已提供该计算，新策略默认仅作影子评审；正式推荐仍走旧路径：

```python
from math import isfinite

VALUE_WEIGHTS = {"cute": 0.20, "contrast": 0.30, "charm": 0.25,
                 "unique": 0.15, "funny_strength": 0.10}


def value_score(llm: dict | None, weights: dict | None = None) -> float | None:
    """新结构返回 0–1；旧结构或证据维度不全返回 None，由调用方区分处理。"""
    if not llm or type(llm.get("value_schema_version")) is not int or llm["value_schema_version"] != 1:
        return None
    w = VALUE_WEIGHTS if weights is None else weights
    if set(w) != set(VALUE_WEIGHTS):
        raise ValueError("五维权重字段不完整")
    if any(isinstance(v, bool) or not isinstance(v, (int, float))
           or not isfinite(v) or v < 0 for v in w.values()):
        raise ValueError("权重必须是非负有限数")
    if abs(sum(w.values()) - 1.0) > 1e-6:
        raise ValueError("权重之和必须为 1")
    values = {k: llm.get(k) for k in w}
    if any(isinstance(v, bool) or not isinstance(v, (int, float))
           or not isfinite(v) or not 0 <= v <= 1 for v in values.values()):
        return None
    return sum(values[k] * w[k] for k in w)
```

调用约束：

1. 旧结构继续调用当前 `final_score`，不要重新解释历史数据，原排序与发布选择保持原语义。
2. 新结构维度完整时才算五维分；真实全零得到 0。新结构缺字段、未知或异常时进入待复核，不偷偷退回旧高分。
3. 新路径移除以 `funny` 为唯一价值依据的否决与降权，但保留事实、人物形象、完整性和风险检查。
4. `is_pick`、同场比较和模板选择必须一起调整。新价值路径已解除 `funny=True` 的唯一门槛；正式推荐仍通过显式旧路径保持原行为，不能只换评分函数就认为整条发布链已切换。
5. 新阈值使用独立的 0–1 配置 `value_pick_score`，不要把旧 `pick_score=8` 直接套到新分数；当前配置 0.65 为影子实验初值，仍需版本化人工样本校准。
6. 现有校准网格只搜索旧权重，旧审核标注也偏重好笑；不能声称它们已经能学习新的五维权重。新评审标准应版本化，并用不同场次验证。

## 九、落地顺序与验收

| 顺序 | 工作 | 验收 |
|---|---|---|
| P0 | 明确关注目标、数据来源、主价值与未知值语义 | 同一片段能由不同审核者解释为何有价值；缺失指标不冒充零 |
| P0 | 新旧 schema 与标题字段兼容、旧路径保护 | 旧结果排序不变；funny 布尔值不进入五维强度；全零和缺字段分开 |
| P1 | 非峰值候选与失败分流 | 有预算内的新增有效召回；可修复内容不被静默过滤 |
| P1 | 起止点完整链路与萌点模板试剪 | 短内容不因统一时长下限被强行补长，明确起点不被后续规则反复推翻 |
| P1 | 同一批素材影子排序与人工盲审 | 同时记录新旧次序，不直接覆盖旧结果，不触发自动投稿 |
| P2 | 包装实验、固定稿龄快照与复盘 | 标题兑现、观察周期与版本可追溯；缺少归因时不下涨粉因果结论 |

先修兼容与评价口径，随后让召回和模板进行小规模验证；不先批量重跑所有历史场次，也不先开启新策略自动发布。

当前实现核对（2026-11-17，含本次未提交实现）：

- 兼容与隔离：正式评审继续使用原版 `rerank_v4`、旧 `final_score` 和旧发布选择；独立 `rerank_value_v1` 输出到 `value_llm`，另存 `shadow_rank / shadow_pick / shadow_route / shadow_reasons`，不覆盖正式推荐。每场原候选前 5 条额外影子评审，配置 `value_shadow_top_n` 可设为 0。全零不回退，缺失、布尔冒充分数、非有限值和未知版本待复核。推荐阈值作用于五维原始分，粗筛加分不负责“抬过线”。
- 证据与分流：所有非零维度要求来源、秒数、具体引用及理由；原话、弹幕需能匹配实际素材，画面秒数需对应输入截图。画面解读仍由人确认。新策略分为风险/证据待复核、可修复、低价值、正常；`not_funny` 不再作为价值路径的否决理由。影子同场比较独立按价值排序、重叠事件去重，最多提出 3 条人工选择建议，不调用旧好笑比较覆盖结论。
- 召回：粗筛不再因弹幕不足 20 条直接跳过整场。默认每场另存最多 5 条非峰值探索（最多可设 10），包含逐字稿线索、确定性时段抽样及人工标记；默认线索方法为本地短语启发式，不能称为完整语义理解。审核页可选择额外语义召回，最多 3 次模型调用、每次 6000 字，覆盖整场不同位置；真实引用核验、重叠合并和调用记录一起保存。探索输出单独的 `exploration_candidates.json / exploration_rerank.json`，不占用正式序号或触发自动投稿。
- 边界与剪辑：明确短内容不按统一下限补长；无效、倒序、超出素材的时间会修正并保留前后轨迹。初稿阶段也保护明确短范围。修复萌点模板文件名；编辑器可手动选择默认/萌点，萌点仍需证据和风险检查，并强制最多 3 个效果、放大不超过 1.15、去除自动配乐和呼应插片、保留原声。未确认的影子评审不会自动切换正式模板。
- 包装：兼容旧标题数组与结构化建议，拒绝数值标题、重复项和新结构的越界证据索引；发布包保存评审版本、引用和候选标识。封面多版本、叠字、自定义补充和已有版本选择沿用现有功能。空旧标题数组也可回退新字段。影子包装建议需人工核对并采用，不直接代替已编辑标题或生成图。
- 回流：抓取来源、时间、缓存状态与绑定/抓取/有效数量分开；缺失指标不填零。新增 SQLite 固定稿龄快照，24h 允许延后 1 小时采集，7d 允许延后 6 小时；错过窗口不伪造历史值。已保存观察不可覆盖，重复事件仅计一个独立样本；每组显示数量、范围和离散程度，低于 5 个样本明确不足。旧累计类型汇总仅作描述，不当作固定稿龄实验结论。
- 目标与归因：分别记录切片号关注、主播关注、主播回访；手动录入需明确来源、目标、观察窗口和对应播放量，只有与快照匹配才计算每千播放。既有 `followers` 不自动改解释为这些指标。页面支持新观众适配标记及事件编号，最近 10 条约 6 条是选择目标，不参与评分加权。
- 人工评审与实验：提供随机顺序盲审 CSV、独立答案映射、版本化跨场标注校准及实验计划命令。五维校准至少 3 场 10 条有效独立盲审，按场次留出验证，只有训练和留出场同时改善才提出权重建议，永不自动应用；它衡量审核一致性，不能证明涨粉因果。实验计划记录假设、预算、停止条件、旧策略对照和观察周期，不执行投稿。

使用入口：

1. 场次审核 → **价值评审 / 探索**：召回、人工时间标记、探索评审、快审下查看分流与证据；盲审隐藏 AI 结论。
2. 成片编辑 → **AI 初稿**：人工选择模板。萌点模式仍需有通过核验的价值评审，证据不足时说明原因并停止该模板生成。
3. 精排记忆 → **价值策略复盘**：查看稿龄样本、补充归因、新观众适配与同事件编号；点“采集到期快照”只查询到期稿件；录入归因后“只用本地数据更新”。
4. `python scripts/value_review.py export output/kiya/场次/rerank.json` 导出盲审 CSV。用不同场次填好的 CSV 和各自 `.blind.keys.json` 运行 `calibrate`，详见该脚本帮助；答案映射不要交给盲审人员。
5. `python scripts/value_review.py experiment --out experiment.json --hypothesis '本轮只检验一个包装变化' --budget 10 --stop-rule '事实或形象风险立即停止'` 创建人工实验记录，不自动投稿。
6. Linux 可安装 `deploy/admin/kiya-value-metrics@.service` 和 `.timer`，再启用 `kiya-value-metrics@kiya.timer`，每 15 分钟检查到期窗口。单次最多查询 30 条，快照落在 `output/<主播>/_memory/value_metrics.sqlite3`；新旧发布数据与快照需一并备份。代码已提供，部署时才会启用定时采集。

验证边界：本轮最终相关 Python 回归 122 项通过、4 项因本机缺少字体工具跳过，后端 31 项通过；前端生产构建及桌面/手机假接口浏览器核验通过。不批量重跑历史场次，不在测试中生成付费图片或真实投稿。仍需真实素材与已确认的投稿样本验证五维权重、模板观感、手机封面可读性与关注/回访效果；代码完整和测试通过不等于效果假设成立。可选语义召回是预算内抽样，非全场穷举；固定稿龄快照依赖采集任务按时运行和接口可用。

## 十、保留决策与复盘问题

保留：涨粉优先的阶段方向；五维初始配比；不做互斥赛道；反差不做强制送审；暂不扩大多平台和正式栏目。

每轮复盘只回答几件事：哪些内容原本没被找到？新观众能不能看懂并记住主播？剪辑是否兑现了素材价值？数据足以支持什么、还不能支持什么？下一轮只改变哪一个主要环节？
