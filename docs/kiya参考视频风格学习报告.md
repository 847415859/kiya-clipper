## 1. 分析覆盖与可信边界

- 24 条全部读取了时长、分辨率，并生成每条 11 张的总览，共 264 张。
- 对两条用户指定参考及《我画地为牢》《禁言凶手》《律师函》另外做了每秒一张的加密采样，共 561 张。核心两条查看了覆盖全片的逐秒图序；其他样本以总览画面初查为主。
- Windows 中文 OCR 用于辅助检索画中文字；识别可能把描边字幕、英文、弹幕和用户名混在一起，不能直接作为准确原话。
- 24 条全部完成本地 Whisper base 语音转写，共 906 段机器分段。转写是机器初稿，口误、英文、昵称和结尾音乐处有明显识别风险，不能不经核对写入成片字幕。
- 视觉变化检测只用于定位可能有切换、贴图或转场的位置。它也会响应人物动画、变色和片尾，**不等于剪切次数或真实 EDL**。
- 视频没有上传到云端。分析产物位于 `worker/output/_reference_study/kiya/`，在 Git 忽略的输出目录内；语音分析工具及模型位于本机临时工作目录，未增加生产环境依赖。
- 没有参考作品对应的原始录播，暂时无法还原被删掉的等待、全部源时间或精确判断某段是否回放。以下时间均为参考成片内时间，采样误差约一秒，不是可直接执行的切点。
- 本轮没有进行完整的人工听音、音效归类、BGM 曲目或混音测量；视觉观察与机器转写不能替代这些工作。

## 2. 最重要的学习结论

样本的主要价值在于把一轮互动编成有因果关系的小故事：

**问题或触发弹幕 → 主播表达 → 观众反馈 → 改口、解释或嘴硬 → 反应收束。**

包装动作通常能解释为：让观众看清问题、看见反应、注意关键词，或在解释后补一个评论性笑点。不能把同类包装平均分布到所有片段。

同一目录包含不同作品形式，不能全部揉成一个“热闹风格”：

| 样本组 | BV 号 | 本轮用途 |
| --- | --- | --- |
| 互动与梗点包装，13 条 | BV1XPSUBmESk、BV18CDDBXEen、BV1VP7Y6hEDC、BV1M6GA6dEbT、BV1uxbC6jEPi、BV1tg8X63ERs、BV1qUtA65Ep4、BV1u3bA6eEym、BV1a9hJ6dETr、BV1ybpw66E4w、BV1GJp469Eur、BV1C2pk6nEVQ、BV1woWu6bEuj | 本轮主要参考池；仍需按事件分别选用柔和反应或误导喜剧方向 |
| 自然表达、关系与观点，3 条 | BV1EiK66aE2z、BV12LK46BEbZ、BV11v3w6jEfy | 用于学习少包装、表达完整；不默认加入密集梗图 |

## 5. 补充样本给出的约束

- **《我画地为牢》BV1woWu6bEuj**：开头约 0–3 秒背景模糊并突出一句设题文案，5 秒附近切回人物；中段仍有大量正常表达。结尾约 121 秒插入全屏反应画面，133 秒附近出现感谢观看。说明强包装集中在组织信息和段落收尾处，不必持续遮挡人物。
- **《律师函》BV1VP7Y6hEDC**：开头展示提问；约 54.6 秒人物旁有服饰类示意图；101.4 秒是动画角色反应画面。示意物和评论性插入需要明确其编辑性质，不把贴图当成原直播事实。
- **《禁言凶手》BV1a9hJ6dETr**：开头模糊背景突出弹幕；42.8 秒附近冲击线配合人物回应；79.4 秒附近有反应图；结尾三连。它与参考 B 同属互动强调，但不据此推断音效、语速和切点完全相同。
- **《早起成功》BV1EiK66aE2z**：采样中画面基本围绕人物与字幕自然推进。用于防止“有互动就必须密集整活”的过拟合。
- **《夜车》BV13cVs6dEHn**：光效、描边与歌词式排版明显不同，独立保留为音乐参考，不拿其变化频率控制日常剪辑。

## 6. 可执行的选段与包装原则

### 选材

1. 优先寻找“对新观众可理解的一轮互动”，为提问、回答、转折、反馈分别保留证据时间。
2. 热度是发现线索，不自动决定起止；看清弹幕问题可能比最响的笑声更早。
3. 有误导或悬念的素材，找不到解释或揭示时进入待复核，不推荐仅保留误导部分。
4. 同一话题可以含多个小反应；不要用“只允许一个笑点”的规则直接截断后续互动。
5. 真实思考、尴尬或等待回应的停顿可能有叙事价值；重复营业、无关等待则应提出删除建议。每次删除给出理由和断句检查，不以静音长度一刀切。

### 包装

1. 显示真实提问 → 回人物作答 → 在关键反应短暂强调 → 恢复正常画面。
2. 字幕分为原话字幕、真实弹幕摘录和编辑评论三类，分别记录证据与样式。编辑评论不得伪装成主播原话。
3. 样片两种主要字幕风格可分别学习，不能把“统一黄色”当作所有视频的默认审美。
4. 局部放大需要明确关注对象：人物、某条弹幕、一个实际界面元素。只有缩放而没有取景对象无法复现这些样本。
5. 加载、问号、指示、金币、乌鸦、领奖台等对应不同编辑含义，先判断触发条件，再选资源；没有适配素材时省略。
6. 全屏反应插入、重复强调与常规贴图是不同剪辑能力，不应全部降级成角落里的一张静态图。
7. 三连或日程片尾作为独立模块，不能把它的时长和镜头变化计入主体内容风格。

## 7. 与当前系统的具体差距

| 项目 | 代码现状核对 | 下一步实现 |
| --- | --- | --- |
| 完整互动 | 已有 `event.py` 事件结构及边界方案，文档仍标注为待开发，需另行核对各调用链覆盖 | 把问题、回答、揭示、反应等必要节点交给选段校验，缺节点不能宣称完整 |
| 自动片中删除 | `edit.py`、`render.py` 已支持 `cuts` 与保留区间；`autoedit.py` 的 `EditOut` 主要为 `trim/items/note` | 增加有理由的删除建议、保留停顿与断句检查，并确保两条时间轴正确映射 |
| 原录播与成片映射 | 目前仅有成片证据 | 增加源素材区间到成片区间的显式映射，之后才能可靠学习删减、重排与回放 |
| 弹幕取景 | 已有弹幕文本上下文与缩放，未发现独立的真实弹幕裁切编辑类型 | 增加弹幕证据及截图区域定位，支持背景虚化、短暂阅读、恢复人物画面 |
| 多模态编辑理解 | 精排有少量截图，自动初稿主要接收文本 | 在关键时段追加连续画面与可用的声音信息，不让文本模型臆测表情或语气 |
| 特效能力 | 当前主类型为 text/zoom/sticker/narration/fakeui | 明确区分全屏插入、模糊/暗角、画面变色和回放等能力，不能只靠多加 `items` |
| 风格配置 | `variants.py` 主要表达克制/标准/热闹和数量预算 | 用本研究的事件结构、取景、字幕与触发规则约束初稿，强度档位作为第二维度 |
| 声音 | 本轮只有机器转写，未完成完整混音分析 | 单独标注原声、音效、BGM、静音与进入退出，不照搬未知曲目或凭字幕推断听感 |

## 8. 下一轮样片验收

推荐先做同一段素材的“纯净剪辑 / 柔和互动反应 / 误导—澄清喜剧”对照；只有素材本身具备对应内容时才生成该方向。

验收顺序：

1. 新观众能否理解问题及回答对象。
2. 开头是否直接进入有效内容，解释和收尾是否完整。
3. 是否删掉了必要停顿、改坏语义或留下重复等待。
4. 每个镜头变化、字幕强调和贴图是否有明确的内容触发。
5. 字幕是否准确，画面是否遮挡，声音是否压过原话。
6. 风格是否接近参考，记录用户具体采纳和删除的动作。

这一轮尚缺当前不满意成片与对应原录播的成对样本，不能据参考文件反推系统某一条候选具体错在第几秒。规则保存后需要接入并实际渲染样片验证，不把研究文档完成等同于成片效果已经提升。
