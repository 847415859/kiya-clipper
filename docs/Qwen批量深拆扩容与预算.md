# Qwen 批量深拆扩容与预算

用户已确认本轮新增预算上限 **250 元**。全片分析额度 170 元，精拆与复核额度 80 元。目标优先覆盖可洛的合格投稿，同时扩大有剪切证据、声画复核和制作配方的精拆样本。现有三条可洛视频是首批校准样本，复用原始结果与 v2 时间轴修复。

## 覆盖与精度

| 层级 | 范围 | 交付 |
| --- | --- | --- |
| 全片内容分析 | 优先覆盖清单中 636 条可洛合格投稿 | 每条覆盖从开头到结尾的内容结构，记录前情、关键表达、反应、收束、声画线索以及相应时间和缺口 |
| 第一批完整精拆 | 目标 24 条可洛作品，包含通过验收的现有试跑 | 语义编排图、关键段切前切后、台词触发、字幕与插入方式、声音作用、复核记录、适用条件及反例 |
| 追加精拆 | 可洛近期样本优先，按题材、制作方式、时长和证据价值扩展 | 每加一批回答一个尚未覆盖的制作问题，保留低包装和不适用案例 |

沿用十五分钟以内非回放和近期权重规则。先完成阶段 B/C 的账本与缺口修复，验收第一条完整案例后自动处理另外两条。再分批推进可洛的全片分析与 24 条精拆目标，优先处理近期作品。较短完整作品和较长作品都需要覆盖全片。片段按内容组织，重点段落局部加密，按需补原分辨率、相邻帧与实际音频。通过定位区间和候选观察只能计入对应层级。

## 预算推算与停机

从现有合格清单按 45–60 秒、重叠 5 秒模拟切块，得 2,255–2,903 个片段。每块各跑一次视觉及听音，首遍约 4,510–5,806 次请求。用历史视觉每 30 秒约 18,272 输入 Token、每 60 秒约 36,092 输入 Token，以及音频每秒约 12.5 Token 估算，视觉输出假设每块 1,900，音频输出假设 1,300。北京公开价下首遍原始声画请求约 194–206 元，尚未包含整片汇总、复核、失败和重新分析。实际账号地域、部署范围与计费以账单为准。[视觉价格](https://help.aliyun.com/zh/model-studio/qwen3-vl-plus) · [听音价格](https://help.aliyun.com/zh/model-studio/qwen3-omni-flash)

按同一切块和计价方法，可洛 636 条的原始声画首遍估算约 120–127 元。170 元池覆盖首遍调用、整片汇总及相关失败处理。80 元池覆盖现有三条补采和复核，以及后续精拆的增量调用。前三条和首批常规样本完成后，用实际成本更新可完成数量。两个额度分别记账，复用的首遍结果只计一次。此前 47 次请求仍留在历史总账，250 元指本轮新增支出。636 条和 24 条是工作目标，最终完成量按实际成本和验收结果报告。

全片分析每批建议 20–30 条。每批报告实际成本、失败原因、各层新增完成数、每分钟首遍费用和每条精拆增量费用，更新后续可完成数量。运行前先修结构失败诊断和真实计费记录，核对账号适用计价，再按批自动推进。请求前检查两个额度及 250 元总额，合计已发生费用、未知用量预留、在途预留和下一次请求的保守估价。预计超出对应额度时停止该路径的外部调用，并继续额度内的其他工作。缓存命中另记，失败请求占用额度。累计到 200 元报告一次，额度内自动继续。连续出现同类校验错误时先修原因，再用小样验证并恢复该路径。此前建议的 5 元、24 次以及初期校准 30 次成功调用上限由本轮额度替代。

## 批量执行优化

旧试跑的 45 次请求中有 18 次结果未通过校验。放大规模前，优先把单片段 CLI 接到统一续跑入口，再用现有三条验证以下改动。已有预算足够时，验证通过后按计划自动推进。

| 优先级 | 改动 | 验收方式 |
| --- | --- | --- |
| P0 | 用持久任务账本管理视频、区间、模态、分析阶段和版本。请求前原子登记尝试与费用预留，响应后落盘用量及状态。未尝试、已发送但结果未知、已有回包但校验失败各自计数。 | 模拟在发送后、保存前中断。重启后保留未知请求和费用预留，已有结果只消费一次，未知请求优先核对再决定重试。 |
| P0 | 将错误分成请求配置、限流、网络、响应截断、JSON、字段、时间原点或单位。保存脱敏诊断、响应标识和已收到的用量。按错误选择退避、修参数、缩小区间或隔离。 | 一个视觉块失败时，其已成功的音频保留。同类错误持续出现时暂停该路径，验证修复后再恢复。 |
| P0 | 分开缓存媒体准备、原始模型观察和语义汇总。媒体按源文件版本、区间和编码参数复用。模型按模型、片段哈希、任务、提示词、输出结构和参数复用。绝对坐标按当前来源重新映射，下游汇总更新时复用上游证据。 | 重启同一批次时已成功片段命中缓存。修改汇总提示词仅重算汇总。核对 55 秒、165 秒偏移和疑似秒/毫秒异常。 |
| P1 | 全片首遍使用短结构输出，保留整片时间和内容线索。用首遍结果选关键段，再补原分辨率、相邻帧、听音或声画解释。普通段落与低包装反例也纳入抽样。 | 同一批样本对照 45 秒和 60 秒分块，比较每分钟实际成本、结构失败率、关键事件漏检和跨块衔接，按结果选默认值。 |
| P1 | 按各模态成功输入、可用观察、语义节点和关键动作复核分别汇报覆盖。证据引用应定位到请求中的具体观察与成片时间。每批抽查开头、中段、尾部及有冲突的观察。 | 旧失败被成功覆盖后，从实际缺口移出。时间已在范围内但单位可疑的观察进入隔离。节点必须说明内容和依赖，并能回看证据。 |
| P1 | 先单并发校准，再按实际限流与费用预留提高并发。FFmpeg 准备、模型调用和语义汇总分阶段控制队列，媒体缓存与报告分别管理。 | 重启能续跑，队列中的费用预留总和可核对，磁盘占用与失败率随批次可见。 |

45 秒视觉块按历史用量粗算约 27,180 输入 Token，60 秒实测约 36,092。45 秒方案可能落在较低输入档，但会产生更多块和听音请求。比较单位有效分析成本时应把重叠、失败和合并工作一起计入。试跑样本可覆盖普通互动、密集插入及跨块长段，模型和采样参数以验收结果为准。

批量化的首个技术交付应是可恢复的执行入口和一份干跑清单，其中列出每批视频、按模态拆分的请求数、预计费用、已有缓存、实际缺口和验收状态。首批常规样本通过后，每批继续记录花费、全片完成量、精拆完成量、实际缺口和下一批预计费用。按现有 170 元与 80 元两项额度执行。
