## 3. 必须分六遍研究，不能只写综合感想

### 第一遍：全片内容与人物表达

每条全片研究必须明确：

- 具体发生什么，人物在回应谁/什么。
- 看点来自语言、观点、互动、反应、反差、人物特点还是其他内容。
- 新观众需要哪些前提，哪些信息不能删。
- 每个真实内容节点的进入、结束、对应原话或行为。
- 节点间的因果、问答、解释、递进和回扣关系。
- 哪里是事件结束，哪里是额外尾梗或 CTA。

先建立内容骨架，不用“可爱、有趣、综艺感”充当内容描述，不强迫每条作品都有反转。

用最大 60 秒、建议重叠 5 秒的块读取全片，边界按真实时长调整，不超过文件末尾。分块时间只是调用范围，不是事件边界。跨块合并后检查提问与回答、铺垫与兑现是否被断开，重叠区间去重。

### 第二遍：逐段与逐镜的画面语言

先用连续视频查找真实变化，再对关键接点补更短视频、密集帧或原分辨率截图。

每个显著画面动作记录：

| 维度 | 细拆要求 |
| --- | --- |
| 切换 | 切前是什么、切后是什么、触发词或动作、是否完成信息交接 |
| 构图 | 全景/人物近景/对象局部，人物位置、裁切区域与恢复时机 |
| 运动 | 突然放大还是渐变推近，是否随动作或语言强调；无证据不猜精确参数 |
| 弹幕与对象 | 实际展示什么、观众能否读完、何时回到人物反应 |
| 插入 | 贴图还是全屏短片，进入/退出、与主线的关系及返回方式 |
| 持续状态 | 暗角、模糊、背景和图形持续区间，不按每帧重复计效果 |
| 克制 | 哪些段落主动保留原画面或减少效果，承担什么内容任务 |

“逐镜”指可观察的成片画面/状态单元，不等于还原源录播每一次删除或重排。每秒一帧不具有逐帧精度；精度必须与证据一致。

### 第三遍：字幕、花字与编辑者表达

区分原话字幕、真实弹幕、编辑评论、对象标注与素材自带文字，记录：

- 原文与出现区间；不确定字保留未知。
- 断句、分行、强调词、出入时机与阅读时间。
- 字号、位置、描边、配色与人物/原画面之间的层级，数字无测量依据时用定性或区间。
- 同一句话的普通字幕和强调字幕是否承担不同作用。
- 编辑者是否增加解释、反讽或观众视角，是否可能改变原意。

小字看不清时读取原分辨率局部图。CLI 默认视频缩放不足以证明所有字都已读清，OCR 只作定位，不能升级成真实字幕核验。

### 第四遍：实际声音与节奏

输入原区间声音，不给音频模型看视觉结论来诱导一致。分别记录：

- 关键台词、说话/笑声/等待的时间；不需逐句完美转写才能研究。
- 原声、音乐、音效和插入素材声音的可听关系。
- 声音先入、延续或停止与画面变化的相对时间。
- 停顿用于阅读、思考、反应、期待还是其他任务，解释与事实分开。
- 插入是否遮盖台词、改变气氛或拖慢节奏。

音量、响度和音频事件用适合的工具测量；波形或 ASR 不能替代听音。无法确认声音名称时描述听感，不强行匹配素材名。默认单声道研究输入不能支持空间声道结论。

### 第五遍：段落编排与全片节奏

把内容节点、画面动作、字幕和声音按同一成片时间轴对齐。对每一重要段落回答：

1. 观众进入前已经知道什么，还不知道什么？
2. 先展示问题、结果、反应还是前情？为什么这样安排？
3. 什么时候增加信息，什么时候允许观众读、等、理解或笑？
4. 插入素材服务于哪一节点，拿掉后损失什么？
5. 揭示之后是否还有必要反应、找补、观众回击或澄清？
6. 结尾是否完成主线，有无冗余尾部？

形成具体节点图，不交“未知进入→未知转折→未知结束”作为已完成成果。假想删掉/提前/延后某节点的影响属于分析假设，未经实际样片不能说已证明。

### 第六遍：反例、迁移与配方

对每个有价值案例至少讨论适用条件、失效条件、与 kiya 的差异以及当前系统能否执行，不机械要求每条产生同样数量的规律。

将同类案例关联成：

```text
内容条件 → 必需节点 → 信息顺序 → 注意力目标
         → 剪切动作 → 字幕/声音/插入 → 退出/收束 → 无素材回退
```

单例保留为案例，多个独立近期事件有证据并检查反例后，再归纳候选规则。不要把可洛人物设定、特有关系和私梗直接复制给 kiya。

## 4. 调用与研究编排的具体做法

先运行配置检查；不要输出 Key 或读取完整凭证到对话：

```powershell
py -3.11 worker/scripts/qwen_research.py --check
```

现有片段入口示例，实际末块时长必须动态计算：

```powershell
py -3.11 worker/scripts/qwen_research.py --video worker/output/_reference_study/recency_pilot_v1/BV1nFnG6WEDH/proxy.mp4 --start 0 --duration 60
```

默认 `both` 会分别调用视觉和音频，最多两次请求；不能把一次 CLI 当成一次付费调用。已有匹配缓存时复用，`--refresh` 不得用于盲目重跑全部区间。

现有 `QwenResearchClient.analyze()` 提供通用模态观察。为了真正细拆，执行模型应在独立研究脚本中构造以下步骤：

1. 对实际收到的观察作整片内容汇总，引用源结果，不直接复制摘要。
2. 生成关键接点和疑问清单，只对必要区间追加媒体证据。
3. 按内容理解、剪切、字幕、声音、编排的具体问题调用已授权模型；需要新增提示词参数/媒体方式时实现研究适配并验证，避免复制生产逻辑。
4. 定向调用的缓存键必须包括任务、完整提示词、模型、媒体内容哈希、区间、参数与 schema 版本；不能复用同媒体但不同问题的旧答案。
5. 独立复核先看媒体形成事实，再比较初分析。只有同一模型时明确标记同模型复核；执行模型综合推理若没有直接媒体输入，只能标为基于引用证据的解释。
6. 生成分镜和编排结论后执行结构、时间、路径、模态和语义支持检查；失败最多两轮定向补采，不确定项隔离，其他内容继续。

不要把模型回传的秒数当成自动精确定位。结构化时间使用成片绝对毫秒，保留局部区间、换算依据、误差或采样精度；视觉和声音描述一致不代表已测得严格同步。

## 5. 工作量、费用和自主执行

先盘点现有配置中的实际授权额度与已发生调用，沿用任务书预算边界；不需要用户逐条确认是否继续。

当前任务书的“无明确新预算时，额外计费校准最多 30 次成功调用”仍有效；已发生的真实联调调用计入同一校准账本，不能换目录就重新获得额度。区间视觉/音频请求、针对性补看和复核都计调用，缓存命中另记。

预算优先级：**第一条完整深拆质量 → 其余两条 → 深拆扩样 → 全量 L1**。先估算整片首遍与关键补看的开销，给复核预留额度；不能把额度全用在粗看后宣布“只能等待人工”。

若已有明确全量预算，直接执行并持续记账。若当前额度不足以达到细拆标准，则停在对应资源边界、保留具体剩余任务、汇总一次预算需求，继续本机整理与素材工作；不能降低深度标准凑“完成”，也不能无限调用。

## 6. 每条视频的最低交付

```text
<video_id>/
  CASE_STUDY.md                 按内容顺序讲清全片，不能只有机器状态
  content_nodes.json           真实语义节点、原话/行为、依赖及观看任务
  shot_and_edit_log.jsonl       可见画面动作、切前/切后、进出与证据
  subtitle_analysis.jsonl       文本层来源、文字、样式和作用
  audio_analysis.jsonl          实际听音观察及不确定项
  audio_visual_alignment.jsonl  声画关系，事实与解释分栏
  sequencing_graph.mmd         具体内容节点与依赖图
  recipe_candidates.jsonl       有依据的单例配方，或明确不足
  review_results.json           核对通过、矛盾和未解决项
  evidence_index.json           可回看的媒体/帧/音频/调用引用
```

所有动作关联成片时间；每条结论追溯到真实输入与调用。报告应先放一个完整关键段落的逐项分析，再给整体总结。展示必要截图或片段索引，避免只有大段文字。源媒体和生成帧不提交 Git。

本批总报告还需包含：近期三条的差异与共性、暂定剪切手法目录、编排技艺目录、kiya 适配、素材与开发缺口、覆盖与成本、后续任务。

## 7. 验收与退回条件

以下任一情况不得标为“精细深拆完成”：

- 只有接口成功、像素变化、ASR/OCR 或固定时间桶，没有实际内容与制作动作。
- 声称理解声音但只提交了无声视频或转写。
- 镜头记录没有具体前后画面、时间、触发内容和证据。
- 编排图没有具体事件，或把所有视频都套成同一种反转模板。
- 只分析开头，没有覆盖主要看点、结束与跨块关系。
- 规则没有适用/失效条件，或声称模型结论就是人工确认、生产批准。
- 没有交代未观察区间、模态缺失和时间精度。

允许诚实的局部未知；不要求模型编造所有字、音效名称、源剪切和作者意图。影片制作目的属于解释，有证据支持也不能当作作者亲口说明。
